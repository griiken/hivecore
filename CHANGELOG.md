### Added

- **HITL approval — session-cache key fix (ADR-029 Rev 6).** `SessionCache` was keyed `(tool_name, sha256(input))` — over-engineered outlier vs all four prior systems. Direct manual source verification (no agent) on 2026-05-03: Codex MCP keys `(server, connector_id, tool_name)` with NO arguments (`mcp_tool_call.rs:1196-1200, 1745-1748`); Codex exec uses `prefix_rule(["git", "status"])` token-prefix; pi has no cache (stateless `runner.ts:775-787`); Goose keys tool-name. Hivecore now matches: keys by `tool_name` alone. User picks "Allow for session" on `edit_file` once → every subsequent `edit_file` call passes regardless of args. Closes the "5 prompts for one logical refactor" fatigue. Argument-glob precision (B3 backlog) preserved as forward-compat — API signatures still accept `input`. `sha2` dep dropped from `hivecore-tool-policy/Cargo.toml`. 165 tests pass (was 163); 2 new in `cache.rs`. Clippy clean.

- **HITL approval — ACP `session/request_permission` adapter (ADR-029 Rev 5).** Editor HITL end-to-end. Hivecore agents mounted in Zed / VS Code / Cursor (or any ACP-aware client) now surface real JSON-RPC permission prompts when risky tools fire. New `PermissionRequester` trait + `AcpPrompter: impl Approval` in `hivecore-acp-server/src/bridge.rs` (SDK-agnostic — translates `AcpPermissionDecision { AllowOnce/AllowAlways/RejectOnce/RejectAlways/Cancelled }` to `ApprovalDecision`). `ConnectionSender: impl PermissionRequester` in `bin/main.rs` sends `RequestPermissionRequest` with `ToolCallUpdate { status: Pending }` + 4 standard `PermissionOption`s via SDK `cx.send_request(...).block_task().await`. Critical fix: `PromptRequest` handler refactored to `cx.spawn(...)` the prompt turn — without this, the first approval round-trip would deadlock the dispatch loop (per `agent-client-protocol-0.11/jsonrpc.rs:2881-2906` — counter-requests are only safe in spawned tasks). `ensure_session` extended with `tool_hooks: Vec<Arc<dyn ToolHook>>` parameter; bin builds `ApprovalHook` per session with `OnRequest` + `ToolNameMatcher::coder_defaults()`. Default-on, env opt-out `HIVECORE_NO_APPROVAL=1`. MCP actions surface as `mcp__<server>__<tool>` qualified name. Spec MUST honored: `session/cancel` → `RequestPermissionOutcome::Cancelled` → `ApprovalDecision::Cancelled` → `HookOutcome::ManualAttention`. Non-exhaustive future-proof on `RequestPermissionOutcome` (unknown variants → Cancelled, safe-default). 163 tests pass (was 157); 6 new in `bridge.rs`. Clippy clean.

- **HITL approval A2 — static tool exclusion (ADR-029 Rev 4).** Continue.dev `exclude` shape (`extensions/cli/spec/permissions.md:5-9`). New `apply_exclude(tools, names) → Vec` helper in `hivecore-tool-policy/src/exclude.rs` — pure list filter, no trait, no driver patch. `hivecore-coder --exclude bash,write_file` CLI flag drops named tools from the registry before `ToolRegistry::new`. Defense-in-depth: model can't call a tool it can't see; cheaper than `Deny` matcher (no token cost for hidden tools). Filter applies after builtins + MCP + browser have all registered. Read-only investigation mode = `--exclude bash,write_file,edit_file,browser_act`. Dynamic mode-driven exclusion (plan-mode rebuilds mid-session) deferred to v0.2 (touches `hivecore-agent-loop`). 157 tests pass (was 153); 4 new in `exclude.rs`. Clippy clean.

  - **A6 — `explicit_yes_required: bool`** field on `ApprovalRequest` (Aider `io.py:812, 908`). Destructive ops require literal `y`, default-Enter denies. `CliPrompter` renders distinct copy when set.
  - 13 deferred patterns documented in ADR-029 Rev 2: A2 (`exclude` tool from model's list), A3 (MCP `read_only_hint` consumption), A4 (`ApprovalScope::Group` for multi-file patches), B1-B9 (inspector pipeline, 4-scope settings hierarchy, persistent `AlwaysDeny`, `PrincipalType`, mode mutability mid-session, etc.). - **Browser harness v0.2 — `WaitCondition` predicates + MutationObserver settle loop (validated).** Two HIGH-priority gaps from the v0.1.1 validation report closed:
  - **`WaitCondition` no longer lies.** Single `poll_until` helper at 100 ms cadence (gsd-browser pattern). All 11 variants now have real evaluators: `Delay`, `Load`, `DomContentLoaded`, `SelectorVisible`, `SelectorHidden`, `RefVisible` (bridges via stamped `[data-hivecore-ref]` selector → `wait_selector`), `UrlContains` (Rust `String::contains`), `UrlMatches` (Rust `regex::Regex`, compiled once — gsd-browser doesn't have regex; we improve on the prior art), `TextVisible`/`TextHidden` (`document.body.innerText` substring match), `NetworkIdle` (JS-side `PerformanceObserver` for resource entries; v0.2 polish: route via CDP `Network.requestWillBeSent`).
  - **MutationObserver settle loop.** New file `crates/hivecore-browser-runtime/src/settle.rs` — `ensure_mutation_counter`, `settle_after_action`, `SettleOptions`, `SettleResult`. JS observer install + read-state byte-equivalent to gsd-browser's `cli/src/daemon/settle.rs` (Apache-2.0 + MIT, attributed in file header per ADR-024). Window keys renamed to `__hivecoreMutationCounter*` to avoid host-page collision. Defaults: `timeout_ms=1500`, `poll_ms=50`, `quiet_window_ms=120`. Constants `ZERO_MUTATION_THRESHOLD_MS=60`, `ZERO_MUTATION_QUIET_MS=30` match gsd verbatim. Replaces the prior `tokio::time::sleep(50ms)` placeholder. Settle reason now surfaced in `ActionOutcome.note` (`zero_mutation_shortcut | dom_quiet | url_changed_then_quiet | timeout_fallback`).
  - Live e2e at `examples/wait.rs` — drives all 6 new variants with positive + negative timing assertions. Results: `selector_visible #late` → 213 ms (target ~200 ms), `selector_visible #never-exists` → 625 ms timeout (target 600 ms), `text_visible` (already-present substring) → 2 ms, `text_hidden` (already-absent) → 1 ms, `url_contains` / `url_matches` → < 100 ms. All consistent with 100 ms poll cadence + eval overhead.
  - Three rounds of OSS validation. Reports: `.research/browser-harness-validation.md` (round 1), `.research/browser-harness-postfix-validation.md` (round 2 — initial postfix), `.research/browser-wait-and-settle-validation.md` (round 3 — wait + settle). All three sign off "ready to ship".
  - `regex = "1"` added to `hivecore-browser-runtime`.
  - **Documented v0.2 trade-offs (intentional, not bugs):** (a) `NetworkIdle` uses JS `PerformanceObserver` not CDP `Network.requestWillBeSent` (misses WebSocket/SSE/in-flight fetches), (b) `SelectorVisible`/`TextVisible` don't pierce shadow DOM (gsd uses `queryAllDeep`), (c) `TextVisible` is case-sensitive (gsd is case-insensitive). Each is a trivial v0.2 fix.
- **Browser harness v0.1.1 — validation pass + 9 fixes from prior-art audit.** Two-round validation against `gsd-build/gsd-browser`, `microsoft/playwright-mcp`, `1jehuang/jcode`, and the `chromiumoxide` upstream issue tracker (#292, #320, #296) found and we landed:
  - **JS-eval click** (chromiumoxide #320 hang) — `Element::click()` was hanging on real pages; now dispatched via `call_js_fn("function() { try { this.focus({preventScroll:true}); } catch(e) {} this.click(); }")`.
  - **JS-eval fill / type with React `_valueTracker` workaround** — replaces CDP `Input.insertText` with prototype-setter dance: `Object.getOwnPropertyDescriptor(proto,'value').set.call(this, v)` + `dispatchEvent(new Event('input', {bubbles:true}))` + `change`. Without this, every controlled-input React/Vue form silently failed post-fill.
  - **Shadow DOM walker** — `collectQueryRoots(scope, out)` recurses `el.shadowRoot`. Web-component sites (YouTube, Salesforce, modern GitHub file viewer) now snapshot correctly.
  - **Stricter visibility check** — adds `opacity:0`, `[hidden]` attr, `visibility:collapse` filtering. Drops offscreen wrappers and decorative-zero elements.
  - **`find_element` 5s timeout** (chromiumoxide #292) — wraps in `tokio::time::timeout`; on hang returns `BrowserError::StaleRef` rather than blocking forever.
  - **Dropped `heading`, `img` from actionable role list** — informational, not actionable. Inflated snapshots 5–10× on content pages with non-actionable refs the agent had to scroll past.
  - **Dropped `tabpanel`, `gridcell`, `columnheader`, `rowheader`** — over-included vs gsd-browser; pollutes data-table snapshots.
  - **Added `<summary>`, `<details>`, `<label>`, `contenteditable`, `menuitemcheckbox`, `menuitemradio`, `<a>`-without-href filter** — match gsd-browser's `interactive` mode.
  - **`SnapshotElement.enabled` field** — collected from JS (`isEnabled` reads `disabled`+`aria-disabled`); wired into the Rust struct + a `HashMap<id, enabled>` runtime map. `act()` now returns `NotActionable("@v3:e7 (disabled in current snapshot)")` for disabled targets and `StaleRef` for unknown ids — semantically correct error mapping.
  - **Renamed DOM attribute `data-hcr-ref` → `data-hivecore-ref`** — clearer namespace for any host page inspecting the DOM.
  - **Hard `LIMIT = 200` per snapshot + `truncated: bool` flag** — token-economy on large pages.
  - **`accessibleName` resolves `aria-labelledby`** — was missing entirely.
  - **Iframe enumeration: report-only, no walk for v0.1** — chromiumoxide's top-level `Page::find_element` cannot traverse iframe contentDocument; refs inside frames would be unactionable. v0.1 reports cross-origin and same-origin frames in `cross_origin_frames` field; per-frame routing via CDP `Target.attachToTarget` is v0.2.
  - **50 ms settle delay** before post-action re-snapshot (placeholder; full MutationObserver-based quiet-window settle loop is v0.2 — concrete failure mode is "fast SPA route change" where re-snapshot fires during loading-state mutation).
  - Examples updated: `examples/smoke` asserts `heading` is **not** in actionable list (validation fix #5), `examples/act` verifies post-click DOM update via button `aria-label` change rather than `<h2>` text (heading no longer in actionable list). Live e2e: open → navigate → snapshot → fill → click → re-snapshot reads updated `document.title`.
  - Validation reports: `.research/browser-harness-validation.md` (~280 lines, round 1) and `.research/browser-harness-postfix-validation.md` (~250 lines, round 2 sign-off). Both committed to research dir; intel doc + ADR-028 reference them.

### Security

- Multi-tenant isolation is enforced at the WASM extension boundary by capability (extensions can only call `host.log` and `host.get-setting`). FS / network / syscalls are off — adding a capability requires an ADR.
- `WorkspaceRoot::resolve` rejects `..`, absolute paths outside the root, and symlink escapes (canonicalises before containment check).
