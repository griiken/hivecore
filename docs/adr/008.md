# ADR-008 · 2026-04-29 · TDD spike-then-attach development workflow

**Decision.** All non-trivial work happens on a `spike/<topic>` branch. The spike must produce a passing scenario file in `scenarios/` before being hardened with tests, docs, and ADRs. Only proven, tested, documented work merges to main.

**Context.** Hivecore is the SDLC harness others will use. Building hivecore with a discipline that enforces "validation replaces review" makes hivecore eat its own dog food and produces a stronger reference implementation.

**Alternatives considered.**
- **Trunk-based with feature flags** — fine for established projects; immature for greenfield.
- **GitFlow with long-lived branches** — too much process overhead for a small team.
- **Pure feature branches** — risks merging before scenarios pass.

**Consequences.** Slower per-PR throughput; higher per-PR confidence. `spikes/` directory accumulates discarded experiments — gitignored to keep main clean. Clean main = clean ledger of proven decisions.

**Revisit when.** Project velocity becomes the binding constraint and a lighter-weight workflow can preserve quality.
