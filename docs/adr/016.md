# ADR-016 · 2026-04-30 · Two-layer runtime split (Layer 1 runtime / Layer 2 substrate / Layer 3 opinionated harness)

**Decision.** Hivecore is split into two stable layers and one opinionated layer:
- **Layer 1 — Runtime.** I/O-free agent loop, tool/event/extension/model traits. Crates: `hivecore-runtime-core`, `hivecore-models-core`, `hivecore-tools-core`. Behavioral spec mirrors `pi-mono`'s `pi-agent-core` package (`Agent`, `AgentEvent`, `AgentTool`, `convertToLlm`, `beforeToolCall`/`afterToolCall` hooks, sequential/parallel tool execution, `transformContext`).
- **Layer 2 — Harness substrate.** Sessions, extension host, command/skill registry, provider impls, builtin tools. Crates: `hivecore-runtime-io`, `hivecore-sessions`, `hivecore-extension-host`, `hivecore-models-providers`, `hivecore-tools-builtin`, `hivecore-config`, `hivecore-skills`, `hivecore-commands`. Behavioral spec mirrors `pi-mono`'s `pi-coding-agent` package (extension API surface, JSONL tree session format, slash commands).
- **Layer 3 — Opinionated harness ("hivecore-classic").** UOK seven planes, gates, audit, KG, tenancy, TOML personas/workflows/policies. Crates: `hivecore-orchestrator-core`, `hivecore-gates`, `hivecore-audit-core/io`, `hivecore-kg-core/io`, `hivecore-tenancy`, `hivecore-workflow`. Built as the default Layer 2 extension. Forkable per org.

Layer dependencies: 3 → 2 → 1, never reverse. Layer 1 has no I/O. Layer 2 is the substrate orgs build on. Layer 3 is the default harness; orgs can replace it wholesale.

**Context.** Studied three OSS prior-art codebases (`badlogic/pi-mono`, `zed-industries/zed`, `warpdotdev/warp`) plus `gsd-build/gsd-2`. All three working harnesses cleanly separate a generic agent runtime from the opinionated workflow surface that sits on top of it. pi-mono's `pi-agent-core` (generic) vs `pi-coding-agent` (CLI-specific) is the canonical split. GSD-2 is itself one large extension on top of `pi-coding-agent` — direct validation of the layered model. Without an enforced split, hivecore's core would silently couple to UOK/KG/tenancy specifics and lose the substrate property orgs need to fork freely.

**Alternatives considered.**
- **Single-layer monolith** — every concern in one crate tree. Faster to ship v0.1, but breaks the "fork per org" thesis. Rejected — kills the substrate value prop.
- **Two layers (no Layer 3 distinction).** Bake UOK + KG into Layer 2. Cleaner numerically, but couples opinionated harness to substrate. Rejected — substrate must stay neutral.
- **Four+ layers (split Layer 2 further).** Over-engineering at this stage; revisit if Layer 2 grows unwieldy.

**Consequences.**
- Layer 1 (`*-core` crates) keeps the I/O-free rule from `CLAUDE.md` enforceable by `cargo check` — Layer 1 crates have no I/O dependencies in `Cargo.toml`.
- Orgs can fork Layer 3 alone and keep upstream Layer 1+2 updates flowing in.
- ACP alignment (ADR-018) and WASM extensions (ADR-017) plug into Layer 2 cleanly.
- v0.1 MVP can ship Layer 1 + minimum Layer 2 + a stub Layer 3 ("classic-lite") without committing the full UOK design.
- Cost: extra crate boundaries and a re-export discipline.

**Revisit when.** Layer boundaries blur in practice (e.g., Layer 1 needs I/O for streaming) or one of pi-mono / gsd-pi reorganizes their split in a way that exposes a different cleavage line.
