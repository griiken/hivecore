# ADR-020 · 2026-04-30 · v0.1 MVP scope: smallest-believable harness

**Decision.** v0.1 ships a vertical slice through all three layers, ruthlessly scoped:

**In scope:**
- Layer 1: `hivecore-runtime-core` (Agent, AgentEvent, Tool trait, hooks: `before_tool_call`, `after_tool_call`, `transform_context`); one model adapter (Anthropic via `hivecore-models-providers`).
- Layer 2: `hivecore-sessions` (JSONL tree format, pi-derived); `hivecore-extension-api` v0.1 WIT (just `register_tool` export); `hivecore-extension-host` running one example WASM extension; `hivecore-tools-builtin` (read, write, bash, grep — minimum); `hivecore-config` (TOML schema for one persona); `hivecore-acp` server stub speaking the ACP subset Zed needs to mount us.
- Layer 3: minimal Plan, Execution, Gate (typed outcomes only), Audit (JSONL only, SQLite projection deferred), Tenancy (in-memory context, single tenant supported).
- KG: in-memory only. Three node types: Persona, Workflow, Decision. No retrieval filter yet (single-tenant).
- Demonstrable: one persona defined in TOML, runs against a real repo, produces an audit log, ACP-mounted in Zed.

**Out of scope (deferred to v0.2+):**
- Multi-tenant retrieval isolation (Tenancy plane is stub-only in v0.1).
- Postgres + pgvector + RLS for KG (in-memory only).
- GitOps plane (status-only mode in v0.1).
- Full UOK gate set (only `pass`/`hard-fail` in v0.1; `retryable-fail`/`manual-attention` v0.2).
- Web UI, board, daemon (Phase 4+).
- Skills, prompt templates, slash commands beyond `/help` and `/reload`.
- MCP server mode.
- Multiple model providers.
- Workflow DAG engine (single linear workflow only).

**Acceptance criteria.** (a) one persona TOML config validates and dispatches a unit; (b) audit log JSONL contains `event_id/trace_id/turn_id/caused_by/tenant_id/payload` for every event; (c) Zed mounts the hivecore agent via ACP and runs a turn end-to-end; (d) one WASM extension registers a tool that the persona invokes successfully; (e) all `cargo check / test / fmt / clippy / pnpm lint / typecheck / test` pass on CI.

**Context.** Building Layer 1 + 2 + 3 + KG + multi-tenant + WASM + ACP all at once = years of work. v0.1 must prove the thesis with the minimum to be believable. Zed's 200-crate workspace and gsd-pi's 60-extension surface are end-state references, not v0.1 targets.

**Alternatives considered.**
- **v0.1 = Layer 1 only.** Easy ship, weak proof — agent loops are a solved problem; that's not what hivecore is selling.
- **v0.1 = Full UOK + multi-tenant.** Right end-state, wrong starting point. Cannot ship in any reasonable timeframe.
- **v0.1 = Layer 2 ACP server only.** Useful interop, but no orchestration thesis demonstrated.
- **v0.1 = single layer, all features.** Mixes concerns; first refactor would be brutal.

**Consequences.**
- v0.1 timeline target: 8–12 weeks at full focus.
- v0.5 (thesis credible — multi-tenant KG, full gates, three personas) target: 6–9 months from v0.1.
- v1.0 (stable extension API, ecosystem starts) target: 12–18 months.
- Anything not in scope is in `docs/roadmap.md` v0.2+ explicitly; no scope sneaks back via PRs.

**Revisit when.** v0.1 ships and learnings invalidate any in/out-of-scope call; or a stakeholder requirement (e.g., PMG Workbench Phase 7 acceptance) forces an item back in.
