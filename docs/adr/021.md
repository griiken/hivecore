# ADR-021 · 2026-04-30 · Persona → Agent rename (industry alignment)

**Decision.** The thing we call a configurable system-prompt + tool-allowlist + model-selection bundle is renamed from **"Persona"** to **"Agent"**. TOML key changes from `[persona]` to `[agent]`. Env vars `HIVECORE_PERSONA*` → `HIVECORE_AGENT*`. Type names follow: `Persona` → `Agent`, `PersonaLoader` → `AgentLoader`, `PersonaRegistry` → `AgentRegistry`.

**Context.** Earlier ADR-007 picked "Persona". Survey of the field — Claude Code (`.claude/agents/`), Codex (`SubAgentSource`), Zed (`SpawnAgentTool`), pi-mono (`agents/` dir), GSD-2 (sub-agent `.md` files) — shows "agent" is the universal noun for this concept. "Persona" historically came from chatbot voice-and-style configuration, which is a strict subset of what we configure. Diverging from convention makes hivecore harder to discover for users coming from Claude Code or Codex.

The relational term **"sub-agent"** is reserved for an agent that's been spawned by another. The file format and registry are uniform: the same `[agent]` TOML defines both "the main session's agent" and "an agent eligible to be spawned as a sub-agent".

**Alternatives considered.**
- **Keep "Persona".** Cheap. Costs discoverability + creates a one-off vocabulary users need to translate.
- **Use "Subagent" everywhere.** Awkward when the file isn't actually being spawned by another (e.g. a top-level session). Claude Code's UX has the same naming wart; we don't need to copy it.
- **Use "AgentDefinition".** Verbose. `Agent` + `AgentLoop` + `AgentLoader` already coexist cleanly across crates.

**Consequences.**
- TOML files written against ADR-007's `[persona]` schema must be re-keyed to `[agent]` before they load. (No deployments yet, so no migration tooling needed.)
- ADR-007's prose stays valid in spirit; the *word* "persona" should be read as "agent" everywhere it appears.
- Sub-agent routing (`agent: <name>` in skill frontmatter) now reads naturally — "use the agent named X".

**Revisit when.** A new file format (e.g. JSON for editor integration) or a new framework (e.g. LangGraph) compels a third naming.
