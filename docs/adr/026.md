# ADR-026 · 2026-05-01 · Session log + resume + compaction architecture

**Decision.** Sessions are persisted as append-only JSONL (`<sessions_dir>/<tenant_id>/<session_id>.jsonl`). Compaction never mutates the on-disk log — it appends a `Custom { kind: "compaction_marker", visible_to_model: false, payload: { covers_up_to, summary, kept_tail_start, file_refs } }` message. The model payload sent each turn is **derived** from disk by `ContextTransform::transform_outgoing` walking the message log, finding the latest marker, and rebuilding `[real user messages preserved + synthetic-assistant(SUMMARY_PREFIX + summary) + tail after marker]`. Resume = replay disk → seed `AgentState.messages` → driver fires the same transform → identical shrunk payload. A new Layer-3 crate `hivecore-compaction` ships the default `SummarizingTransform`, `TokenThresholdHook`, and `EmergencyDropHook`. The 10 specific calls are listed under **Decisions** below.

**Context.** Inspecting five OSS coding agents at HEAD on 2026-05-01 (Codex, pi-mono, jcode, Zed, Warp) plus on-disk inspection of Claude Code session JSONL gave us the prior-art map. Three (Codex, pi, jcode) ship the same core pattern: append-only disk + derived payload via marker. Two (Zed, Warp) keep summary as additive metadata over SQLite — different mental model, doesn't fit our JSONL substrate. Layer 1 (`runtime-core`) already has the primitives required: `AgentMessage::Custom { visible_to_model: false }`, `ContextTransform` trait, `LifecycleHook` trait. Driver does NOT call `transform_outgoing` today — that's the wire point.

Critical questions had to be cross-validated against actual source via DeepWiki (not just blog claims). Two of our initial picks flipped after validation: (a) we initially planned to drop pre-cut user messages (pi/jcode shape); Codex's `process_compacted_history` keeps real user messages and only filters dev/non-user content; for an SDLC harness where user turns carry task statements, requirements, and mid-flight corrections, Codex's preservation is the safer default. (b) We initially planned to compute system-prompt overhead at boot; pi's configurable constant (`reserveTokens = 16384`) is simpler and matches what well-engineered prior art ships.

**Decisions (the 10 calls).**

1. **Token estimate.** Use last response's `usage.prompt_tokens` when available; fall back to `chars / 4` heuristic over current `state.messages`. Pi+jcode shape.
2. **Compaction shape — keep real user messages.** Drop assistant + tool-result turns; keep all user turns; append synthetic assistant message containing `SUMMARY_PREFIX + summary_text`. Codex shape (`process_compacted_history` retains real user messages). Pi/jcode drop everything; we deliberately diverge for SDLC reliability.
3. **Sub-agent transcripts** — own JSONL at `<sessions_dir>/<tenant_id>/<parent_id>/subagents/<child_id>.jsonl`. Pi pattern. Cleaner tenancy, audit, replay than Codex's "events forwarded to parent only".
4. **Summarization model** — defaults to chat model. Per-agent override `[agent.compaction] summarization_model = "..."` (Zed-inspired). Propagates to sub-agents.
5. **Mid-turn `ContextWindowExceeded`** — handled at agent-loop level (unanimous: Codex `run_turn`, pi `_checkCompaction`, jcode `try_auto_compact_after_context_limit`). Adapter returns typed error → driver inner-loop catches → fires `EmergencyDropHook` → `messages.remove(0)` + retry. No retry storms — bounded N.
6. **System overhead reservation** — `reserve_tokens = 16384` configurable, per-agent override. Pi pattern (default 16384 tokens for system prompt + tool schemas).
7. **Lock file** — advisory `<session_id>.jsonl.lock` written on session open, removed on close. Second process refuses with `session in use, --fork` message. No prior art for this — added defensively because hivecore embeds into multi-process scenarios (CLI + ACP server + scheduled agents).
8. **Tenant in path** — `<sessions_dir>/<tenant_id>/<session_id>.jsonl`. v0.1 single-tenant uses `tenant_id = "default"`. Schema migrations are pain — pay the layout cost now.
9. **Marker schema** —
   ```rust
   AgentMessage::Custom {
       kind: "compaction_marker",
       visible_to_model: false,
       payload: {
           covers_up_to: MessageId,           // last message folded into summary
           summary_text: String,
           kept_tail_start: MessageId,        // first message kept verbatim
           file_refs: Vec<FileRef>,           // structural file payload (Pi pattern)
           tool_calls_summarized: usize,
           original_turn_count: usize,
           created_at: DateTime<Utc>,
           trigger: CompactionTrigger,        // Manual | AutoThreshold | Emergency
       }
   }
   ```
10. **Summary prompt** — vendor pi-mono's structured-Markdown form (MIT-compatible) at `crates/hivecore-compaction/prompts/summary.md`; vendor Codex's `summary_prefix.md` (Apache-2.0) at `crates/hivecore-compaction/prompts/summary_prefix.md`. Both permitted; document sources in `prompts/README.md` like ADR-024 mandates for upstream prompts.

**Thresholds (configurable, defaults from jcode).**
```toml
[agent.compaction]
threshold = 0.80                   # background compaction fires
critical_threshold = 0.95          # emergency drop-oldest path
manual_min_threshold = 0.10        # /compact refuses below this
recent_turns_to_keep = 10          # tail preserved
min_turns_to_keep = 2              # never strip below
emergency_tool_result_max_chars = 4000
reserve_tokens = 16384
```

**Crate layout.**
- `hivecore-runtime-core` — no change. Trait already present (`Custom`, `ContextTransform`, `LifecycleHook`).
- `hivecore-agent-loop` — wire `transform_outgoing` before each `model.complete`; add `Builder::resume(messages)`; add `Builder::context_transform(...)`.
- `hivecore-persistence` — already has `SessionWriter` (impls `EventSink`) + `SessionReader`. Add `session_index.jsonl` (Codex pattern: append-only, scan-from-end), tenant-prefixed paths, lock-file write/release on open/close.
- `hivecore-compaction` (NEW) — `SummarizingTransform`, `TokenThresholdHook`, `EmergencyDropHook`, vendored prompt files, default constants (overridable per-agent).
- `hivecore-coder` — `--continue / --session <id|name> / --name <handle>` flags; default-wire `SessionWriter` and `SummarizingTransform`.

**Resume CLI shape (Claude Code).**
```
hivecore-coder --continue              # latest by cwd
hivecore-coder --session <id|name>     # explicit
hivecore-coder --name <handle>         # set human-readable name; persisted in session_index.jsonl
```

**Alternatives considered.**
- **Mutate disk on compaction (Codex/pi/jcode default behavior coupled).** Lossless replay impossible. Rejected — hivecore needs full audit trail per ADR-019; KG ingestion benefits from raw history.
- **Summary as additive metadata only, full log always sent (Zed/Warp).** Doesn't shrink payload — defeats the purpose of compaction for our use case.
- **Drop user messages entirely (pi/jcode).** Risks losing task statements, requirements, and mid-flight corrections. Rejected for SDLC reliability.
- **SQLite storage (Zed/Warp).** Trades JSONL simplicity for queryability we don't need v0.1.
- **Compute system overhead at boot.** Worth it eventually but `reserve_tokens` constant is simpler and matches pi's well-engineered choice.

**Consequences.**
- v0.1 ships single-source-of-truth disk format. ADR-019 audit JSONL is *one event class within* the same file structure (per the recommendation in `.research/compaction-and-sessions.md`).
- Resume across process restarts is free — no special "resume mode" code path; same driver replays disk + applies transform.
- KG ingestion gets clean structured input via `compaction_marker.file_refs`, `compaction_marker.tool_calls_summarized`. No need to re-parse summary prose.
- Multi-tenant isolation enforced at path layer from day one.
- New crate (`hivecore-compaction`) replaceable by orgs that want different policy (Layer 3 forkability per ADR-016).
- Cost: ~600 LOC added across 5 crates. New compaction crate. Driver gets a `transform_outgoing` call site.

**Revisit when.** (a) A model adapter exposes structured cost-estimation that beats our `usage + chars/4`. (b) Tool-result blob sizes routinely exceed `EMERGENCY_TOOL_RESULT_MAX_CHARS = 4000` — re-tune. (c) Sub-agent transcript sharding becomes a perf bottleneck. (d) Multi-tenant retrieval lands in v0.2+ — Tenancy plane may want richer marker payload. (e) Cross-machine session sync (someone wants `hivecore-coder` over a shared filesystem) — lock-file semantics need upgrade to fcntl.
