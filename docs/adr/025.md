# ADR-025 · 2026-04-30 · `spikes/` → `crates/hivecore-*`: full move + rename

**Decision.** Move every v0.1 substrate crate from `spikes/<name>/` to `crates/hivecore-<name>/`, and rename packages from `<name>-spike` to `hivecore-<name>`. The `spikes/` directory is reclaimed for its original meaning — a place for *throwaway* prototypes (only on `spike/<topic>` *branches*, never on main).

**Context.** ADR-008 promised "spike → harden → tests → docs → attach to main". We didn't follow it: the v0.1 substrate landed *in* `spikes/` with full tests and docs. The labels ("spike", `-spike` suffix) said "throwaway prototype"; the code was the production deliverable. Two readings of the same artifact.

The contradiction surfaced when a contributor asked "what is spike vs crate, what are we using?" — the honest answer was "we're calling production code throwaway, which is incoherent." Three options were on the table:

1. **Rename + move now** — chose this.
2. Redefine "spike" to mean "pre-1.0 incubating" — cheap rebrand, but "spike" has strong existing meaning.
3. Hybrid (move only the stable ones) — bikeshedding territory.

**Mechanics of the move.**
- `git mv spikes/X crates/hivecore-X` for each of the ten members.
- Package rename in each `Cargo.toml`: `name = "X-spike"` → `name = "hivecore-X"`.
- Path-dep rewrite: `X-spike = { path = "../X" }` → `hivecore-X = { path = "../hivecore-X" }`.
- Rust source rewrite: every `X_spike::` → `hivecore_X::`.
- Root `Cargo.toml` workspace members re-pointed.
- All ten per-crate `AGENTS.md` headers updated; cross-references replaced.
- Stale `Cargo.lock` files inside crate dirs removed (workspace owns the lock).

**Verification.** `cargo test --workspace` → 110 passed (no regression); `cargo clippy --workspace --all-targets -- -D warnings` → clean.

**Consequences.**
- ADR-008's "spike-then-attach" promise is honoured: spikes that became production code now live where production code lives. Future spikes go on a `spike/<topic>` branch and never land in `main` under that name.
- Versioning: every crate ships `0.1.0`. Pre-1.0, breaking changes likely; per-crate `AGENTS.md` carries the stability notes.
- `git log --follow` on individual files needs the `--follow` flag to trace through the rename. The whole-directory rename uses `git mv` so blame is preserved by default.
- External tooling that pinned a path inside `spikes/` will break. (No external tooling does today.)

**Revisit when.** Any crate hits 1.0 — at that point it should be promoted to crates.io and a separate `hivecore-` namespace decision is needed.
