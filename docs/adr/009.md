# ADR-009 · 2026-04-29 · GSD harness as project-management tool

**Decision.** Hivecore uses GSD (`/gsd-*` skills, currently v1) for phase management. `.planning/` directory is GSD-managed; we do not invent our own process docs structure.

**Context.** GSD already provides spec→discuss→plan→execute→verify lifecycle, atomic commits per task, fresh context per task, ADR extraction, codebase intelligence, cross-AI plan review, and verification phase. Reinventing this is wasteful. The project author already uses GSD daily.

**Alternatives considered.**
- **Hand-rolled phase docs** — reinvents what GSD already does.
- **Linear / Jira + manual notes** — heavier process, harder to dogfood.
- **Plain markdown todos** — too lightweight for the scale of build needed.

**Consequences.** `.planning/` structure follows GSD conventions. Phase commands are GSD slash-commands. The build process itself becomes a reference for how a team can use GSD on a non-trivial project.

**Revisit when.** GSD v2 (Pi SDK) reaches stability and offers benefits (programmatic state machine, crash recovery, auto-mode), at which point migration becomes a separate ADR.
