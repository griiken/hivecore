# ADR-027 · 2026-05-01 · MCP integration architecture (deferred — design-only)

**Decision.** MCP support lives as an **opt-in Layer 3 crate** `hivecore-mcp-client`, bundled by default in `hivecore-coder` and `hivecore-acp-server` (with `--no-mcp` flag), absent from the kernel and from the WASM extension surface. Default registration is the **GSD-2 lazy 3-meta-tool pattern**: the model sees three builtin tools (`mcp_servers`, `mcp_discover`, `mcp_call`); per-server connections fire on first use via a `getOrConnect` cache. Eager mode (Codex pattern — list every MCP tool flattened into the agent's tool list at startup) is available as a builder switch for users with ≤3 servers. SDK = official `rmcp` crate (`modelcontextprotocol/rust-sdk`). v0.1 ships **without** MCP; the design is locked here so v0.2 implementation has no re-research debt.

**Context.** Surveyed five OSS coding agents at HEAD on 2026-05-01 (Codex, Claude Code, jcode, GSD-2, pi-mono) plus the official `rmcp` Rust SDK. Findings in `.research/mcp-integration.md`, `.research/mcp-deep-dive-2.md`. Key signals:

- **4/6 ship MCP kernel-bundled and always-on** (Codex, jcode, Claude, Warp). All four are single-harness products.
- **GSD-2 ships MCP as a single bundled extension** (`src/resources/extensions/mcp-client/index.ts`, ~640 LoC) using `pi.registerTool()`. Auto-loaded but architecturally separable. Critically, **it advertises only 3 meta-tools to the model** and connects servers lazily via `getOrConnect` cache.
- **pi-mono ships nothing.** Author has a published anti-MCP stance.
- **Codex deep findings.** `qualify_tools` enforces `mcp__<server>__<tool>` ≤ 64 bytes with first-12-chars-of-SHA-1 suffix on collision. Sanitization keeps `[a-z0-9_]` only. **No description-size cap.** **`on_tool_list_changed` is just a log line — cache stays stale.** Per-tool approval is in-memory `TurnContext` only, not persisted across sessions.
- **rmcp SDK** (3.3k★) wraps protocol cleanly. Stdio + streamable-HTTP + SSE + WS transports behind feature flags. `ClientHandler` trait owns server-initiated callbacks (`create_message` for sampling, `create_elicitation`, `list_roots`). Default `create_message` returns `method_not_found` — sampling must be explicitly opted-into.

Hivecore's substrate thesis (ADR-016 — Layer 3 forkable per org, multi-tenant retrieval ADR-019) makes the always-on-kernel pattern wrong. An org may want hivecore as a base and replace the entire tool-discovery surface with their own (Linear-MCP-only, GitHub-MCP-only, no-MCP, etc.). Forcing MCP into Layer 1 or 2 violates this. GSD-2's "MCP as extension" + `pi.registerTool()` API is the closest precedent — and our `Vec<Arc<dyn Tool>>` registry is the equivalent extension point.

**Decisions.**

1. **Layer 3, opt-in Cargo dep.** New crate `crates/hivecore-mcp-client`. Same shape as `hivecore-compaction` and `hivecore-builtin-tools` — orgs add a Cargo dep + one wiring call. Not in kernel. Not in WASM extension surface (WASM sandbox blocks subprocess spawn + arbitrary network — would need WIT v0.2+ capabilities that defeat the sandbox).

2. **Bundled in default harnesses, opt-out via flag.** `hivecore-coder` and `hivecore-acp-server` add the crate as a default Cargo dep. Reads `~/.hivecore/mcp.toml` and `<workspace>/.hivecore/mcp.toml` if present, no-op if absent. `--no-mcp` flag turns it off. Custom harnesses opt in by adding the dep — same as compaction.

3. **SDK = official `rmcp` crate.** `modelcontextprotocol/rust-sdk`. Same SDK Codex's `codex-rmcp-client` builds on. Reject hand-rolling (jcode pattern) — keeps spec drift off our plate.

4. **Default registration mode = GSD-2 lazy 3-meta-tool.** The model sees three builtin tools regardless of server count:
   - `mcp_servers` — list servers from config (no connection).
   - `mcp_discover(server)` — connects + fetches tool schemas. Cached.
   - `mcp_call(server, tool, args)` — invokes via `getOrConnect`.

   Reasons: (a) tiny token surface that doesn't grow with server count, (b) sidesteps startup failures from unreachable / un-credentialled servers, (c) cleaner permission story — user grants on first call, (d) smaller prompt-injection surface, (e) Claude Code's "MCP Tool Search" pattern eventually does the same.

5. **Eager mode opt-in via builder.** `McpClient::eager_tools(cfg).await` returns `Vec<Arc<dyn Tool>>` — every MCP tool flattened into the registry at startup (Codex pattern). For users with ≤ 3 servers who want immediate discovery. Same crate, different mode.

6. **Codex algorithms adopted verbatim** (when implementing eager mode + qualifying any MCP tool name):
   - `mcp__<sanitized_server>__<sanitized_tool>` namespace.
   - `MAX_TOOL_NAME_LENGTH = 64` bytes.
   - Sanitize: lowercase ASCII alphanum kept, everything else → `-`, trim, empty → `"app"`, finally `-` → `_`. Allowed final `[a-z0-9_]`.
   - On length-overflow OR collision: append first 12 chars of SHA-1(raw_identity). Truncate `tool_name` first; namespace only as fallback.
   - `ToolFilter { enabled, disabled }` allow/deny on **raw** server-native names, **before** qualification.

7. **Three things Codex got wrong, hivecore fixes.**
   - **`tools/list_changed` triggers cache invalidation + re-list** (Codex just logs it). Otherwise tenant-supplied servers can hot-swap tools and we'd never see the change.
   - **2 KiB hard description cap with truncation marker** (Codex has none). Multi-tenant deployments will see verbose descriptions add up.
   - **Per-tool approval persistence at `(tenant, server, tool)` granularity** in audit JSONL + SQLite projection. Codex stores in-memory `TurnContext` only. Hivecore's tenancy + audit planes (ADR-019) require durable approval state.

8. **`ClientHandler` defaults.** `create_message` (sampling) → unimplemented (returns `method_not_found`); `list_roots` → tenant-scoped roots from tenancy plane; `create_elicitation` → ACP elicitation channel; notifications fan into the `EventSink`. Sampling is explicitly skipped because (a) nobody implements it, (b) it lets MCP servers spend the user's model-tokens on server-supplied prompts — wait for a written security review.

9. **rmcp Cargo features for v0.2 launch.**
   ```toml
   rmcp = { version = "0.8", default-features = false, features = [
       "client",
       "server",                       # required by rmcp 0.8 even for client-only consumers (mis-gate in upstream model/tool.rs)
       "macros",
       "schemars",
       "base64",
       "transport-child-process",
       "transport-io",
   ] }
   ```
   Add for HTTP transport / OAuth: `auth`, `transport-streamable-http-client-reqwest`. Add only if needed: `transport-ws`, `auth-client-credentials-jwt`.

10. **Config schema.**
    ```toml
    # ~/.hivecore/mcp.toml or <workspace>/.hivecore/mcp.toml
    [mcp_servers.github]
    transport = "stdio"                 # default
    command = "npx"
    args = ["-y", "@modelcontextprotocol/server-github"]
    env = { GITHUB_TOKEN = "${env:GITHUB_TOKEN}" }
    enabled = true
    startup_timeout_sec = 30
    tool_timeout_sec = 60
    default_approval_mode = "on_request"   # "always" | "never" | "on_request"
    enabled_tools = []                  # empty = no allowlist (allow all)
    disabled_tools = []

    [mcp_servers.github.tools.create_issue]
    approval_mode = "always"            # per-tool override
    ```

    JSON in `~/.hivecore/mcp.json` accepted as Claude Code import. First-run import from `~/.codex/config.toml [mcp_servers.*]` and `~/.claude.json` (jcode pattern; cheap; reduces onboarding).

11. **Tool result truncation.** `TruncationPolicy::Bytes(1024)` — Codex parity.

12. **Outbound MCP server** (`hivecore-mcp-server` binary) — separate crate, separate decision, deferred to v0.3+. Distribution shape, not a feature. GSD-2 ships an analog (`gsd-mcp-server`).

**Alternatives considered.**

- **Kernel-bundled MCP** (Codex / jcode / Claude / Warp). Industry-aligned but violates substrate thesis. Rejected.
- **WASM extension** for MCP. Sandbox blocks subprocess spawn + arbitrary network. Adding `host.spawn-process` / `host.open-tcp` capabilities to WIT v0.2+ defeats the sandbox purpose. Rejected.
- **Hand-roll MCP** (jcode pattern). Spec drift cost too high. Rejected — use `rmcp`.
- **Eager-only registration** (Codex pattern). Token bloat at scale. Rejected as default; kept as opt-in for ≤3-server users.
- **Lazy-only with no eager mode**. Loses parity with Codex/Claude users who expect tool list to show MCP tools immediately. Rejected — both modes shipped.
- **No MCP at all** (pi pattern). Loses the interop story (Linear, GitHub, Postgres, etc. all ship MCP servers). Rejected — defer to v0.2 but plan it.
- **Sampling support in v0.2.** Server can spend user's model-tokens on server-supplied prompts. Security risk requires written threat model first. Rejected for v0.2; revisit after security review.

**Consequences.**

- v0.1 ships without MCP. v0.2 adds `hivecore-mcp-client` opt-in crate, ~600 LOC.
- Default behaviour: harness sees three meta-tools `mcp_servers / mcp_discover / mcp_call`. Token cost ~3 tool descriptions regardless of how many MCP servers configured.
- Eager mode available for power users — same crate, builder switch.
- Three deliberate divergences from Codex (cache invalidation on list_changed, 2 KiB description cap, persisted per-(tenant, server, tool) approval) are documented; they're real improvements over the most-used reference impl.
- Custom harnesses can fork or omit the crate freely; substrate thesis preserved.
- Sampling deferred — eliminates a class of prompt-injection / token-spending attacks for v0.2.
- Cost: one extra crate, one extra Cargo dep on default harnesses, one config file path to document, three small fix-vs-Codex improvements to maintain.

**Revisit when.** (a) Tenant-supplied MCP servers routinely exceed 5+ — re-evaluate eager mode default. (b) Sampling becomes table-stakes for ecosystem MCP servers (currently nobody uses it) — write security review and add. (c) `rmcp` SDK breaks compatibility — pin version, document migration path. (d) HTTP transport demand surfaces — add `transport-streamable-http-client-reqwest` + OAuth keyring storage. (e) Per-tenant connection pool needed (jcode pattern, scoped to `tenant_id` not process). (f) `hivecore-mcp-server` outbound binary becomes a distribution priority — separate ADR.
