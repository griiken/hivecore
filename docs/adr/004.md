# ADR-004 · 2026-04-29 · Backend language: Rust

**Decision.** Hivecore's backend is written in Rust (axum, sqlx, tokio).

**Context.** The platform's most demanding components — the multi-tenant KG engine with bi-temporal queries, the durable orchestrator with journal-replay, the Firecracker sandbox runner — are all latency- and correctness-sensitive. The Claude Code paper (arxiv 2604.14228) found that 98.4% of an agent's value sits in the deterministic infrastructure around the model. Substrate quality dominates outcomes.

**Alternatives considered.**
- **Go** — simpler, faster compile, larger hire pool. Acceptable if team has zero Rust experience. GC pauses during long agent runs are a real concern.
- **TypeScript** — would unify with frontend, but performance-critical components (KG queries, sandbox lifecycle) suffer.
- **Python** — would speed prototyping but Postgres+pgvector + Firecracker integration is harder; deployment surface heavier.

**Consequences.** Steeper learning curve for new contributors. Best-in-class performance and memory safety. Single static binary deploy. Firecracker integration is native (Firecracker itself is Rust). Reference impl `majiayu000/harness` proves the shape works.

**Revisit when.** Hire pipeline becomes the binding constraint, OR a specific subsystem (e.g., heavy ML training) needs a different language and a multi-lang split is justified.
