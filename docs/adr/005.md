# ADR-005 · 2026-04-29 · Frontend stack: TypeScript + Next.js 16 (App Router)

**Decision.** Hivecore's frontend is TypeScript + Next.js 16 with App Router, React Query for server state, Zustand for client state, shadcn/ui for components.

**Context.** Need a fast, modern, type-safe UI for the board, run viewer, and KG visualizer. Next.js 16 + App Router is the maturity peak for React-based SSR/SSG. tRPC gives end-to-end type safety to the Rust backend (via OpenAPI bridge). React Query + Zustand split is the proven pattern from many Multica-style projects.

**Alternatives considered.**
- **SvelteKit** — leaner, but smaller ecosystem and fewer ITSM-domain plugins.
- **Solid + SolidStart** — fast, but less mature.
- **Vue 3 + Nuxt** — fine choice; team's TS+React experience tips it the other way.

**Consequences.** Excellent DX, mature ecosystem, easy to hire for. Bundles can grow if not disciplined. Server-component / client-component boundary requires care.

**Revisit when.** A meaningful subset of users want a non-React UI, or Next.js's direction conflicts with project needs.
