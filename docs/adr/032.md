# ADR-032 · 2026-05-04 · `SessionStore` trait + tree-shaped session log (supersedes ADR-026)

**Decision.** Replace ADR-026's linear append-only JSONL session log with a **tree-shaped append-only session log** behind a Layer-3 `SessionStore` trait. Hivecore is pre-launch with no users on disk, so this is a clean break, not a migration. Concrete shipped impl: `JsonlStore` (default). Future impls (sqlite, durable-objects, postgres, s3) implement the same trait without touching the agent loop or compaction layer.

ADR-026 is **superseded** by this ADR. The "linear log + stack of compaction markers" scheme is removed entirely. The "disk is source of truth, never mutated; compaction never rewrites history" invariant is **preserved** — the file remains append-only; the only mutability is the in-memory `leaf_id` cursor, which itself is journaled as an entry on every move.

**Trait surface (locked here):**

```rust
// hivecore-persistence/src/sessions/store.rs

pub type EntryId = String;  // 8-char prefix of UUIDv4; collision-checked at allocation

#[async_trait]
pub trait SessionStore: Send + Sync + Debug {
    async fn metadata(&self) -> RuntimeResult<SessionMetadata>;

    async fn leaf_id(&self) -> RuntimeResult<Option<EntryId>>;
    async fn set_leaf_id(&self, id: Option<EntryId>) -> RuntimeResult<()>;

    async fn create_entry_id(&self) -> RuntimeResult<EntryId>;
    async fn append_entry(&self, entry: SessionEntry) -> RuntimeResult<()>;
    async fn get_entry(&self, id: &EntryId) -> RuntimeResult<Option<SessionEntry>>;

    async fn find_entries_of_kind(&self, kind: SessionEntryKind)
        -> RuntimeResult<Vec<SessionEntry>>;

    async fn label(&self, target: &EntryId) -> RuntimeResult<Option<String>>;

    /// Walk parent-pointers from `leaf` to root. Returns root-first order.
    async fn path_to_root(&self, leaf: Option<EntryId>) -> RuntimeResult<Vec<SessionEntry>>;

    /// All entries in append order (for debugging / migration / KG ingestion).
    async fn all_entries(&self) -> RuntimeResult<Vec<SessionEntry>>;

    /// Children of an entry (forwards index built lazily from parent pointers).
    async fn children_of(&self, id: &EntryId) -> RuntimeResult<Vec<EntryId>>;
}
```

**Entry schema:**

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SessionEntry {
    pub id: EntryId,
    pub parent_id: Option<EntryId>,   // None ⇔ root
    pub timestamp: DateTime<Utc>,
    #[serde(flatten)]
    pub payload: SessionEntryPayload,
}

pub enum SessionEntryPayload {
    Message            { message: AgentMessage },
    ThinkingLevelChange { level: ThinkingLevel },
    ModelChange        { provider: String, model_id: String },
    Compaction         { summary: String, first_kept_entry_id: EntryId,
                         tokens_before: u32, file_refs: Vec<FileRef> },
    BranchSummary      { from_id: EntryId, summary: String, file_refs: Vec<FileRef> },
    Label              { target_id: EntryId, label: Option<String> },
    LeafChange         { from: Option<EntryId>, to: Option<EntryId> },
    Custom             { kind: String, visible_to_model: bool,
                         data: serde_json::Value },
}
```

The on-disk JSONL is `{ session header line, then one entry per line }`. `leaf_id` is **not** stored separately — it is recovered on load by replaying `LeafChange` entries newest-first; the most recent `to` value is the current leaf. This preserves "disk is source of truth" without any sidecar file or in-place mutation.

**Replay / outgoing-message derivation:**

```
1. store.path_to_root(store.leaf_id()).reverse()   → root-to-leaf path
2. fold path: collect last Compaction; entries before its first_kept_entry_id are dropped,
   summary becomes a synthetic assistant message at that position
3. fold: each BranchSummary becomes a synthetic system-shaped message at its slot
4. filter: payload kinds that don't produce a model-visible message (LeafChange, Label,
   ThinkingLevelChange, ModelChange) are dropped
5. result is the model payload
```

`AgentLoopBuilder::resume(store)` replays the path, seeds `AgentState.messages` with the derived view, and the driver fires `transform_outgoing` on the next turn. Identical shape to ADR-026's contract, just walking a path instead of a list.

**Branch operations:**

- **Append.** `append_message(msg)` writes a `Message` entry with `parent_id = current leaf`, then writes a `LeafChange { from: old, to: new }`. Both lines are atomic-append (single `write_all` call on JsonlStore).
- **Navigate.** `navigate(target_id)` writes a `LeafChange { from: current, to: target_id }`. Optionally, before that, writes a `BranchSummary` entry for the abandoned path (the entries from current-leaf back to common ancestor with target). Summary generation is an LLM call — gated behind `NavigateOpts.summarize: bool`, default `false`.
- **Fork.** Just a navigate followed by an append. The new message becomes a sibling of whatever was previously the leaf's-parent's child set. No special opcode.
- **Compaction.** Unchanged from ADR-026 in shape — `Compaction { summary, first_kept_entry_id, ... }` entry. Walks the path, marks the cut point. Per-branch by construction (each branch's path has its own latest compaction).

**Context.** ADR-026 shipped a linear log + stack-of-markers. Working, but the architecture forecloses three near-term needs:

1. **Edit-and-retry.** UI-first principle (ADR-014) implies the frontend will let users rewrite a prompt and resubmit. Linear log can't represent two siblings of the same parent without rewriting history (which violates "never mutated"). Tree handles it natively.
2. **Fork-and-explore.** A driver-initiated branch ("try two answers, score, keep winner") is naturally a tree operation. Today this is approximated via `SpawnAgentTool` writing a separate sub-agent JSONL, which works but produces two disconnected logs that humans / KG ingestion have to stitch back together.
3. **Per-branch compaction.** Linear stack-of-markers means a compaction taken on one branch leaks into a sibling branch on rewind. Tree compaction lives on the path, not the file.

ADR-026 also hardcoded the JSONL writer in `hivecore-persistence`. Storage pluggability (sqlite for queryability, durable-objects for edge deployment, postgres for multi-tenant control plane, s3 for archival) was deferred. Putting `SessionStore` in front of `JsonlStore` now is cheap; doing it later means re-touching the agent loop's resume path and `hivecore-compaction`.

Pre-launch is the right window. Post-launch this becomes a JSONL → tree-JSONL migration with users to coordinate.

**Alternatives considered.**

1. **Keep linear log; add a separate `branches.json` sidecar for fork pointers.** Rejected. Two-file truth is fragile (lock semantics, partial writes, replay-time reconciliation). One append-only file + parent pointers is simpler and provably consistent.
2. **Keep linear log; treat each branch as a separate session file.** Rejected. Loses the audit-trail-as-one-thing property; KG ingestion would need to join across N files. Tree-in-one-file is the right granularity.
3. **Tree-in-memory only; linear on disk.** Rejected. Leaf moves don't survive restarts, defeats the resume-across-process-restarts guarantee from ADR-026.
4. **SQLite as the only impl.** Rejected. JSONL is grep-able, diff-able, human-readable. SQLite is a future `SessionStore` impl, not the v0.1 default.
5. **Defer to v0.3.** Rejected. We're pre-launch. The cost of breaking ADR-026 now is zero on-disk; the cost later is a real migration.

**Wiring plan.**

| Crate | Change |
|---|---|
| `hivecore-persistence` | New `sessions/store.rs` (trait + entry types). Rewrite `sessions/writer.rs` and `sessions/reader.rs` as `JsonlStore: SessionStore`. `sessions/index.rs` still indexes session files at the directory level (Codex pattern from ADR-026 §Crate-layout retained). `lock.rs` unchanged. |
| `hivecore-compaction` | `SummarizingTransform` rewrites: replays `store.path_to_root(leaf)`, finds latest `Compaction` payload on the path, drops entries before `first_kept_entry_id`. Marker-stack code removed. |
| `hivecore-agent-loop` | `Builder::resume(store: Arc<dyn SessionStore>)`. `AgentState.messages` becomes a *derived view* recomputed from `store.path_to_root(store.leaf_id())` after every append. Driver appends entries (not raw messages) on each turn. New `Builder::session_store(...)` setter; old `Builder::resume(messages)` removed. |
| `hivecore-coder` | Wires `JsonlStore` from session path; passes to builder. CLI flags from ADR-026 (`--continue`, `--session`, `--name`) keep their semantics, now resolving against the tree store. Adds `--fork-from <entry_id>` for explicit branching from CLI. |
| `hivecore-acp-server` | Same wiring. ACP `session/load` populates `JsonlStore` from path; `session/cancel` no longer needs special tree handling — abandoning a turn just leaves the leaf where it is. |
| `hivecore-config` | Per-agent `[agent.session]` block (already lives there). No schema change for v0.1. |

**JSONL on-disk format (v2 — supersedes ADR-026 v1):**

```jsonl
{"type":"session","version":2,"id":"sess_...","timestamp":"...","cwd":"...","tenant":"default"}
{"id":"a1b2c3d4","parent_id":null,"timestamp":"...","Message":{"message":{...}}}
{"id":"e5f6g7h8","parent_id":"a1b2c3d4","timestamp":"...","LeafChange":{"from":null,"to":"a1b2c3d4"}}
{"id":"i9j0k1l2","parent_id":"a1b2c3d4","timestamp":"...","Message":{"message":{...}}}
{"id":"m3n4o5p6","parent_id":"i9j0k1l2","timestamp":"...","LeafChange":{"from":"a1b2c3d4","to":"i9j0k1l2"}}
...
```

Header line is metadata-only (Codex shape from ADR-026 retained). Every subsequent line is a `SessionEntry`. `LeafChange` entries are themselves entries with their own `parent_id` for KG-ingestion purposes (every fact has a parent in the audit trail).

**Locking, tenancy, sub-agents.** All ADR-026 invariants preserved: advisory `<session_id>.jsonl.lock`; `<sessions_dir>/<tenant_id>/<session_id>.jsonl` path; sub-agents at `<sessions_dir>/<tenant_id>/<parent_id>/subagents/<child_id>.jsonl`. Each sub-agent has its own `SessionStore` instance backed by its own JSONL file.

**Consequences.**

*Enables.*
- Edit/retry/fork/rewind UX in apps/web (P5) without touching persistence again.
- Per-branch compaction (no leak across siblings).
- Sub-agent transcripts can later promote to branches of the parent (single-file audit) — tracked as a v0.2 follow-up, not v0.1 scope.
- Pluggable storage (sqlite / durable-objects / postgres / s3) without re-touching `hivecore-agent-loop` or `hivecore-compaction`.
- Rich KG ingestion: `parent_id` chains feed the Decision/Run subgraphs naturally.

*Costs.*
- ~2,500 LOC across `hivecore-persistence`, `hivecore-compaction`, `hivecore-agent-loop`, `hivecore-coder`, `hivecore-acp-server`. Largest piece is rewriting `JsonlStore` and replay logic.
- Test surface: existing 165+ tests need re-fixturing for the new entry schema. ~30 new tests for tree operations (path-to-root, navigate, fork, per-branch compaction).
- API break for any external `hivecore-persistence` consumer. Pre-1.0, acceptable, called out in CHANGELOG.
- ADR-026 stays in the log (append-only — never deleted) and links to this ADR via the supersedes linkage in the index.

**Revisit when.**
- A `SessionStore` impl other than JSONL ships and reveals an awkward trait method (e.g., `find_entries_of_kind` proves expensive in sqlite without an index hint) — add hint methods.
- Branch summary generation proves load-bearing for context quality — promote `summarize: true` to default and tune the prompt.
- Cross-machine session sync (someone wants `hivecore-coder` over a shared filesystem) — `lock.rs` upgrades to fcntl; `JsonlStore` is unchanged.
- Sub-agent-as-branch lands — extend `LeafChange` with `delegated_to: Option<SessionId>` semantics or add a `SubAgentRef` payload kind.
- Frontend introduces "checkpoint" UI separate from "leaf" — may need a multi-cursor abstraction over `leaf_id`.
