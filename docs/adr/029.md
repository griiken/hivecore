# ADR-029 · 2026-05-03 · Human-in-the-loop approval primitive (design + v0.1 trait surface)

**Decision.** Hivecore introduces a **first-class HITL approval primitive** as a single Layer-1 trait `Approval` in `hivecore-runtime-core` (the *sink* / `Prompter` shape — Layer 3 implementations ask the human) carrying a typed `ApprovalAction` payload (variants `Tool`/`ApplyPatch`/`Mcp` for v0.1) and a 7-outcome `ApprovalDecision` enum (`Approved`/`ApprovedForSession`/`ApprovedAndPersist`/`Denied`/`TimedOut`/`Abort`/`Cancelled`) with a `RiskHint` metadata struct and `ApprovalScope { Call, Turn, Session }` axis. **The driver is not modified.** A new Layer-3 crate `hivecore-tool-policy` ships an `ApprovalHook: impl ToolHook` that bridges the existing `HookOutcome` state machine to `Approval` decisions: `Approve → Pass`, `Deny → FailedContinue { reason }` (pi-mono shape — model sees a synthetic tool error), `Abort → ManualAttention { reason }`, `ApproveSession → Pass + cache hit on subsequent calls`. The crate also owns the auto-decision rules (`ToolMatcher` trait, regex/glob deny-list), the session-scoped cache (`(tool_name, arg_hash) → decision`), and (v0.2) the persistent amendment log. ACP wire shape is `session/request_permission` (no reinvention — already in the protocol). Codex's `ReviewDecision` is the conceptual model; ACP's `PermissionOptionKind` is the wire vocabulary; Warp's `RiskHint` is the auto-decision input. **v0.1 ships the `Approval` trait (already landed in `runtime-core`) + the `hivecore-tool-policy` crate + ACP/CLI prompters; persistent amendments, granular per-category policy, and network-kind defer to v0.2.**

**Revision 1 (2026-05-03 — same day).** Initial draft proposed adding a new `await` site in `dispatch_tools`. Implementation walkthrough at `.research/hitl-implementation-walkthrough.md` showed the existing `ToolHook` state machine (`Pass | Override | FailedContinue | FailedAbort | ManualAttention` — driver.rs:337-350) covers all four user-visible outcomes (approve / deny / abort / session-approve via `Pass + cache`). Codex effectively does the same (its `run_permission_request_hooks` step in `mcp_tool_call.rs:213-218` is the pi-mono `beforeToolCall` shape grafted onto a richer system). Driver stays untouched; approval lands as a Layer-3 hook. Trait surface in `runtime-core` (the `Approval` "ask the human" primitive) preserved as a sink-shaped contract that `ApprovalHook` consumes.

**Revision 2 (2026-05-03 — same day).** Gap audit at `.research/hitl-gap-audit.md` surveyed six unchecked OSS systems (Aider, Cline, Continue.dev, Goose, OpenHands SDK, Claude Code) and surfaced load-bearing patterns the v0.1 design lacked. Three landed immediately to avoid breaking the wire protocol later:

- **A1 — `MatchOutcome { Allow, Ask(reason), Deny(reason) }`** replacing `Option<reason>` matcher result. Hard `Deny` short-circuits without prompting (Claude Code `permissions.deny`, Goose `never_allow`). Today's deny-list always-prompts is fatigue-prone.
- **A5 — `ApprovalPolicy::FailOnAsk`** for headless / CI runs. Continue.dev `--print` mode parallel: `ask` becomes process-exit, not a hung sink. Lands before any ACP/CI integration so non-interactive harnesses don't deadlock.
- **A6 — `explicit_yes_required: bool`** on `ApprovalRequest`. Aider `io.py:812, 908` pattern — destructive ops require literal `y`, default-Enter denies. CliPrompter renders distinct copy. Two-line trait extension; sinks ignore at no cost.

- A3 — Consume MCP `ToolAnnotations.read_only_hint` (Goose) — `hivecore-mcp-client` work, populates `RiskHint.read_only`.
- A4 — `ApprovalScope::Group(GroupId)` (Aider `ConfirmGroup`) — multi-file-patch batch consent.

**Deferred to v0.2 (`ADR-029 v2` / audit-policy plane):**

- B2 — **Inspector pipeline** (`Vec<Box<dyn ToolInspector>>`) — Goose's anchor design move; replaces monolithic `ToolMatcher`. B3-B9 compose into it.
- B3 — Argument-glob matching at rule level (`Bash(npm run test *)`).

**Rejected.** R1 (six-mode flat enum), R2 (Cline two-bit shell split), R3 (yolo-toggle redundant with `Never`), R4 (Aider session-only "don't ask again" — bug not design). Rationale in audit doc.

**Revision 3 (2026-05-03 — same day, A3 LANDED).** MCP `read_only_hint` consumption shipped via verification-driven design (`.research/mcp-tool-annotations-verification.md`). Closed the "user prompted for `git status`" gap. Three pieces:

- **`RiskAugmenter` trait in `runtime-core`** (`approval.rs`) — `fn augment(&self, inv: &ToolInvocation) -> RiskHint`. Layer-3 implementors map invocations to risk metadata; sync (cache lookup is fast path).
- **`AnnotationCache` + `McpRiskAugmenter` in `hivecore-mcp-client`** (`client.rs`, `risk.rs`). `list_raw_tools` now populates the cache as side-effect; `McpRiskAugmenter` parses `mcp_call` invocations, looks up cached annotations, builds `RiskHint`. Per-server `trust_annotations` flag (default `true`) honours MCP spec normative MUST: untrusted unless trusted server.
- **`ApprovalHook::with_augmenter` short-circuit.** Under `policy=UnlessTrusted`, an augmented `RiskHint.read_only == Some(true)` returns `HookOutcome::Pass` without invoking the sink. Under `OnRequest`, hint is informational — sink still asked. Under `Never`/`FailOnAsk`, hint is ignored (already deny-by-policy).

**Goose convention preserved verbatim** (`crates/goose/src/permission/permission_inspector.rs:32-44`): `read_only_hint=Some(true)` is *policy input*, never unilateral auto-allow. `Some(false)` and `None` both fall through to ask. `destructive_hint=Some(true)` surfaces as `RiskHint.risky=Some(true)` for future inspectors (B-track) but does not gate v0.1 decisions.

**Revision 5 (2026-05-03 — same day, ACP `session/request_permission` LANDED).** Editor HITL works end-to-end. Hivecore agents mounted in Zed / VS Code (or any ACP-aware client) now surface real `session/request_permission` JSON-RPC requests when risky tools fire.

- **`PermissionRequester` trait + `AcpPrompter: impl Approval` in `hivecore-acp-server/src/bridge.rs`.** SDK-agnostic: bridge.rs declares the trait taking session_id + tool_call_id + tool_name + raw_input + reason → returns `AcpPermissionDecision { AllowOnce, AllowAlways, RejectOnce, RejectAlways, Cancelled }`. `AcpPrompter` translates: `AllowOnce → Approved`, `AllowAlways → ApprovedForSession`, `RejectOnce/Always → Denied` (v0.1 collapses persistent reject; B5 tracks `AlwaysDeny`), `Cancelled → Cancelled`. MCP actions surface as qualified name `mcp__<server>__<tool>` so the editor can render distinct icons.
- **`ConnectionSender: impl PermissionRequester` in `bin/main.rs`.** Sends `RequestPermissionRequest` (session_id + `ToolCallUpdate { status: Pending, raw_input, title }` + 4 standard `PermissionOption`s) via SDK `cx.send_request(...).block_task().await`. Decodes outcome by `option_id` round-trip.
- **Spawn-pattern fix.** Refactored `PromptRequest` handler to spawn the prompt turn via `cx.spawn(...)` so `block_task()` doesn't deadlock the dispatch loop (per `agent-client-protocol-0.11/jsonrpc.rs:2881-2906`). Responder moves into the spawned task; handler returns immediately. Without this fix, the first approval round-trip would hang the connection.
- **`ServerState::ensure_session(session_id, sink, hooks)` extended** with `Vec<Arc<dyn ToolHook>>` parameter. Caller (bin) builds `ApprovalHook` per session with `OnRequest` policy + `ToolNameMatcher::coder_defaults()`. Default-on; opt-out via env `HIVECORE_NO_APPROVAL=1`.
- **Cancellation.** `RequestPermissionOutcome::Cancelled` (per `client.rs:735` — emitted by client on `session/cancel`) maps to `ApprovalDecision::Cancelled` → `HookOutcome::ManualAttention` → loop bubbles to harness. Spec MUST honored.
- **Non-exhaustive future-proofing.** `RequestPermissionOutcome` is `#[non_exhaustive]`; unknown variants treated as `Cancelled` (safe-default — never auto-allow on unknown).

**Revision 6 (2026-05-03 — same day, session-cache key fix).** `SessionCache` was keyed `(tool_name, sha256(canonical_input))` — fatigue-prone outlier. Direct source verification of four prior systems on 2026-05-03 (no agent — read manually):

- **Codex MCP:** `McpToolApprovalKey { server, connector_id, tool_name }` with **NO `arguments` field**. (`mcp_tool_call.rs:1196-1200`, `mcp_tool_approval_is_remembered` at `:1745-1748`.) `ApprovedForSession` covers all subsequent calls to that tool.
- **Codex exec:** `prefix_rule(["git", "status"])` — token-prefix match, not full-arg-string match. Persistent amendment via `ExecPolicyAmendment`.
- **pi-mono:** No cache at runner level. Stateless. `runner.ts:775-787` — every `tool_call` event re-fires; "remember" is the extension's problem.
- **Goose:** Tool-name set (`permission_inspector.rs:32-44` per gap audit). Same as Codex.

Hivecore now keys by `tool_name` alone — matches majority convention. User says "Allow `edit_file` for session" → every `edit_file` call passes regardless of args. SHA-256 input hashing was a v0.1 over-design. Argument-glob precision (Continue.dev / Claude Code `Bash(npm test:*)` shape) tracked as B3. `SessionCache::key_for` removed; `sha2` dep dropped from `hivecore-tool-policy/Cargo.toml`. API signatures (`contains(name, input)`, `insert(name, input)`) preserve `input` parameter for forward-compat with B3 glob matching.

**Context.** Four prior-art systems surveyed at HEAD on 2026-05-03 (`/.research/hitl-prior-art.md`):

- **pi-mono** — extension `tool_call` event hook + `ctx.ui.confirm` UX primitive. No typed approval state machine. Already rejected by ADR-022 ("events double as gates").
- **OpenAI Codex** — deepest reference. `GuardianAssessmentAction` (6 kinds, one wire shape), `ReviewDecision` (7 outcomes incl. self-amending `ApprovedExecpolicyAmendment`), `PermissionGrantScope { Turn, Session }`, top-level `AskForApproval { UnlessTrusted | OnRequest | Granular | Never }`, and `available_decisions` letting the server pick which buttons to render.
- **Zed ACP** — wire-shape only. `session/request_permission` JSON-RPC method, `PermissionOptionKind ∈ {allow_once, allow_always, reject_once, reject_always}`, `RequestPermissionOutcome { selected | cancelled }`, `ToolCallStatus::pending` as the loop pause indicator. Cancellation contract: `session/cancel` MUST cancel pending requests.
- **Warp** — coarsest. Profile-scoped action categories + regex allow/denylist + risk metadata baked into action variants (`is_read_only`, `is_risky`, `rationale`). Denylist beats allowlist beats YOLO mode. No "approve and persist via UI" — list editing is manual.

All four converge on the same five-question state machine: typed action → policy evaluates (auto-allow / auto-deny / ask-user) → on ask-user, suspend on async oneshot, render typed payload, accept one of {approve-once, approve-persist(scope), reject, abort}.

Hivecore's existing surface already overlaps:
- `crates/hivecore-mcp-client/src/config.rs:79-100` — `ApprovalMode { Always | Never | OnRequest }` and `effective_approval_mode(tool)` resolver. Direct fit for the top-level dial; extract to shared place.
- `crates/hivecore-runtime-core/src/hook.rs` — `ToolHook::before` returns `HookOutcome::ManualAttention(String)`. The escape hatch already exists; it's just unstructured.
- `crates/hivecore-acp-server` — already speaks ACP; adding `session/request_permission` is incremental, not a rewrite.

**Alternatives considered.**

1. **Make HITL a `LifecycleHook` variant.** Rejected. Lifecycle hooks return `LifecycleOutcome { Pass | FailedContinue | FailedAbort | ManualAttention }`. Squashing "approve and remember with typed rule payload" into `ManualAttention(String)` loses the typed amendment. Approval is its own trait.

2. **Reuse `ToolHook::before` as the *only* driver-level mechanism (no new await site).** ✓ ADOPTED after the implementation walkthrough at `.research/hitl-implementation-walkthrough.md`. The typed `Approval` trait stays in `runtime-core` as the *sink* (the human-asking primitive); a new Layer-3 `ApprovalHook: impl ToolHook` consumes it and maps `ApprovalDecision` → `HookOutcome { Pass | FailedContinue | ManualAttention }`. `Approve → Pass`, `Deny → FailedContinue` (pi-mono shape — model sees a synthetic tool error), `Abort → ManualAttention`, `ApprovedForSession → Pass + cache hit thereafter`, `ApprovedAndPersist → Pass + (v0.2) audit writer`. The driver is untouched.

3. **Adopt Codex's full 7-outcome `ReviewDecision` verbatim including `ApprovedExecpolicyAmendment` and `NetworkPolicyAmendment`.** Deferred. Hivecore has no execpolicy engine yet (ADR-007 commits to TOML, not Starlark) and no sandbox plane. v0.2.

4. **Use ACP's 4-kind `PermissionOptionKind` as the canonical decision enum and not reinvent.** Rejected as the *internal* enum. ACP's vocabulary covers 80% of cases but loses (a) typed scope (Turn vs Session), (b) typed amendment payloads, (c) `Cancelled` distinct from `Denied`. Keep ACP as the wire vocabulary; encode the richer hivecore decisions into the opaque `optionId` round-trip.

5. **Subsume policy into `hivecore-config`.** Rejected. `hivecore-config` declares the schema; the policy *engine* (cache, evaluator, amendment writer) is Layer 3 by shape. Mirrors how `hivecore-compaction` is split from `hivecore-runtime-core` (ADR-026).

6. **Skip the new crate and put policy code in `hivecore-agent-loop`.** Rejected. Couples the driver to TOML schema parsing; makes the driver harder to reuse from non-TOML-config harnesses. Separation = cleaner.

**Trait surface (v0.1, locked here).**

```rust
// hivecore-runtime-core/src/approval.rs

pub enum ApprovalAction {
    Tool { tool_name, invocation_id, input_preview, risk: RiskHint },
    ApplyPatch { root, files, changes },
    Mcp { server, tool_name, input_preview },
}

pub struct RiskHint {
    pub read_only: Option<bool>,
    pub risky: Option<bool>,
    pub network: Option<bool>,
}

pub enum ApprovalDecision {
    Approved,
    ApprovedForSession,
    ApprovedAndPersist { rule: ApprovalRule },   // typed amendment (v0.2 honors)
    Denied,
    TimedOut,
    Abort,
    Cancelled,
}

pub enum ApprovalRule {
    ToolPrefix { name_prefix: String },
    McpToolAllow { server: String, tool: String },
    PathRoot { root: PathBuf, write: bool },
}

pub enum ApprovalScope { Call, Turn, Session }

pub struct ApprovalRequest<'a> {
    pub session_id: SessionId,
    pub turn_id: TurnId,
    pub action: &'a ApprovalAction,
    pub reason: Option<String>,
}

#[async_trait]
pub trait Approval: Send + Sync {
    async fn request(&self, req: ApprovalRequest<'_>) -> ApprovalDecision;
}
```

Five types, one trait, no I/O. Stays in Layer 1.

**Driver wiring (v0.1) — no driver patch.** `crates/hivecore-agent-loop/src/driver.rs:337-350` already pattern-matches the full `HookOutcome` state machine produced by `Vec<Arc<dyn ToolHook>>`. The new `ApprovalHook: impl ToolHook` (in `hivecore-tool-policy`) registers via the existing `AgentLoopBuilder::hook(...)` method (driver.rs:524) and maps `Approval::request` results onto `HookOutcome`:

```rust
// hivecore-tool-policy/src/hook.rs
async fn before(&self, ctx: ToolHookContext<'_>) -> HookOutcome {
    let Some(reason) = self.matcher.requires_approval(ctx.invocation) else {
        return HookOutcome::Pass;                 // not in deny-list
    };
    if matches!(self.policy, ApprovalPolicy::Never) {
        return HookOutcome::FailedContinue { reason: ... };
    }
    if self.cache.contains(&inv.name, &inv.input) {
        return HookOutcome::Pass;                  // session cache hit
    }
    let decision = self.sink.request(req).await;
    match decision {
        Approved | ApprovedAndPersist {..} => HookOutcome::Pass,
        ApprovedForSession                 => { cache.insert(...); HookOutcome::Pass }
        Denied | TimedOut                  => HookOutcome::FailedContinue { reason },
        Abort | Cancelled                  => HookOutcome::ManualAttention { reason },
    }
}
```

Driver, runtime-core trait surface, and existing tools all unchanged. The pi-mono `beforeToolCall → {block, reason}` shape (`pi-coding-agent/src/core/agent-session.ts:540-565`) is reproduced 1:1 via `FailedContinue { reason }`. Codex's richer outcomes (`ApprovedForSession`, `ApprovedAndPersist`) are handled inside the hook (cache + future audit writer) rather than at the driver level — the driver still sees `Pass`.

**Layer 3 sinks.**

- **`hivecore-acp-server`** — implements `Approval` by translating to `session/request_permission`. Always emits the four standard `PermissionOption`s (`allow_once`/`allow_always`/`reject_once`/`reject_always`). Amendment-bearing actions append a 5th option whose `kind: "allow_always"` and whose `optionId` encodes the typed `ApprovalRule`. Decoder restores the rule on response. Cancellation: `session/cancel` ⇒ `ApprovalDecision::Cancelled`.
- **`hivecore-coder`** — implements `Approval` over stdin/stdout, four-options, no JSON-RPC.
- **(future)** `apps/web` UI — implements `Approval` over WebSocket.

**Audit (ADR-019 plane).** Two new `AgentEvent` variants:

```
AgentEvent::ApprovalRequested { request_id, action, scope_eligible, at }
AgentEvent::ApprovalDecided   { request_id, decision, scope, at }
```

Persistent amendments (`ApprovedAndPersist`) land in audit JSONL with `Custom { kind: "approval_amendment", visible_to_model: false }`. Replay = re-load amendments → seed `ApprovalPolicy.persistent_rules` → identical auto-decisions. v0.2.

**Multi-tenancy.** `ApprovalRequest` carries `session_id` (from which the policy plane resolves `tenant_id`). Cache key at the policy boundary is `(tenant_id, session_id, action_key)`. Persistent amendments tenant-scoped — no cross-tenant rule leakage. Same isolation invariant as ADR-019/ADR-026.

**Composition with existing ADRs.**

- **ADR-018 (ACP).** Wire shape unchanged. Hivecore agent-server already has a JSON-RPC peer; adding `session/request_permission` is one method handler.
- **ADR-019 (audit plane).** Two new event variants, one new `Custom` message kind. No new persistence target.
- **ADR-022 (lifecycle separation).** `Approval` is its own trait; `LifecycleHook` and `ToolHook` keep their semantics. The `ManualAttention` escape hatch in `ToolHook::before` continues to work — driver maps it through the approval pipeline.
- **ADR-026 (compaction).** Approval events are journaled but `visible_to_model: false`. Compaction's outgoing-message derivation excludes them automatically.
- **ADR-027 (MCP).** Existing `ApprovalMode { Always | Never | OnRequest }` in `hivecore-mcp-client/src/config.rs` becomes the per-MCP-tool override that feeds into the policy plane. No breaking change.

**Consequences.**

*Enables.*
- Real HITL flow when hivecore mounts under Zed (or any ACP client) — pending `ToolCallStatus` + four-option prompt out of the box, no per-client work.
- A typed audit trail of every approval (who decided what, when, on what action) — load-bearing for ADR-019 governance.
- A clean place to add Codex-style self-amending policy in v0.2 without re-shaping the core trait.
- Composable approval sinks: CLI today, web later, Slack/email escalation in P6, all behind one trait.

*Costs.*
- One new Layer-1 trait + module (~150 LOC).
- One new Layer-3 crate (`hivecore-tool-policy`, ~300 LOC v0.1).
- One new `await` site in the hot path of `dispatch_tools`. With no `Approval` wired the driver short-circuits → zero overhead.
- Test surface: ~15 new unit tests across approval types + policy evaluator + ACP/CLI adapters.
- ACP server gains one new request handler.
- Backwards compat: existing `ToolHook::before` returning `ManualAttention(String)` is preserved as an escape hatch; no behavior change for harnesses that don't wire `Approval`.

**Revisit when.**
- Sandbox plane lands → add `ApprovalAction::Network` and Codex's `NetworkPolicyAmendment`.
- Audit plane gains durable persistence → upgrade `ApprovedAndPersist` from no-op to real amendment writer.
- A second non-ACP wire format ships (e.g., gRPC control plane) → confirm `optionId` round-trip encoding still suffices.
- A research finding shows Warp / pi / another reference adopting a richer scope axis than `Call|Turn|Session` → revisit the enum.
- An OSS audit shows a HITL bypass via `ManualAttention` → tighten the escape hatch.

**Open assumptions** (tracked in `.research/hitl-prior-art.md` §10):
- A1 — Warp's pause mechanism (low risk, narrative only).
- A2 — encoding choice for ACP amendment payload (`_meta` vs encoded `optionId`); v0.1 picks encoded `optionId`.
- A3 — `OnRequest` as v0.1 default (vs `UnlessTrusted`); v0.1 picks `OnRequest`.
- A4 — `Approval` belongs in `hivecore-runtime-core` (vs new core trait crate); v0.1 keeps it in runtime-core.
- A5 — audit events visible to model on replay; v0.1 marks `visible_to_model: false`.
