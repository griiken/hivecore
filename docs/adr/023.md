# ADR-023 · 2026-04-30 · Skills are tool-shaped, not prompt-injected

**Decision.** A hivecore skill is implemented as a `runtime_core_spike::Tool`. Its `description()` flows to the model via the standard tool list. Its body is rendered (variable expansion + `` !`<cmd>` `` bash injection) on tool call and returned as the tool result's text content.

A skill with `agent: <name>` frontmatter delegates the rendered body to a sub-agent through a `SubAgentRouter` trait, mirroring Claude Code's pattern verbatim.

**Context.** Codex implements skills as a separate prompt-injection mechanism: descriptions live in the system prompt, bodies are conditionally injected when the model "names" a skill in its output. Claude Code does the same. Both approaches require the agent loop to know about skills.

We could have done it that way. Instead we noticed: the existing `Tool` trait *already* has the right shape — descriptions in a tool list, bodies on demand. Modeling skills as tools requires zero changes to `runtime-core` or `agent-loop`. The whole skill concept lives in `spikes/skills/` as a Layer 3 add-on.

**Context (continued, sub-agent routing).** Claude Code skills can specify `agent: Explore` to fork the rendered body into a sub-agent. We model this as a `SubAgentRouter` trait that the harness wires when it has a sub-agent registry. Without a router, the skill body is returned inline (the v0.1 default).

**Alternatives considered.**
- **Prompt-injection (Codex/Claude Code style).** Requires the loop to be aware of skills. Forces a second "what's a skill" mechanism alongside tools.
- **Special "skill" message kind.** Intermediate option. Adds a wire-format variant just for skills. Rejected — the existing tool-result path serves the same purpose.

**Consequences.**
- Skills compose with everything tools compose with: hooks, audit, allowlist, persistence. No new plumbing needed.
- Description-budget: Claude Code documents a ~1.5 KiB cap on skill descriptions. Tools have no such cap in our impl yet — large skill catalogs will eat tool-list tokens. Add a budget cap in v0.2.
- Bash-injection security: `` !`<cmd>` `` runs in the workspace root with a 30 s timeout. A skill author with write access to the skill dir can run arbitrary commands. Same trust boundary as native tools, but worth documenting.

**Revisit when.** Description-budget bites; or a model emerges that can't see skill descriptions in its tool list (forcing prompt-injection as a fallback path).
