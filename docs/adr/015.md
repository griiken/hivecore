# ADR-015 · 2026-04-29 · Phase 7 first vertical = PMG Workbench (motadata-itsm); PMG head as design partner

**Decision.** Phase 7 (First Vertical) is reframed as "Ship the PMG Workbench" — a workbench used daily by motadata's PMG (Product Management Group) team for plugin authoring, customer customization work, and SDLC automation across the 18-app motadata-itsm stack. PMG head's handwritten requirement note is treated as the canonical V1 acceptance criteria for the first vertical. PMG head becomes a design partner with weekly review starting at Phase 4 demo readiness.

**Context.** PMG head surfaced a workbench requirements list that maps ~80% to hivecore's existing v1 plan (markdown authoring, git+worktree+publish, KG, web-first UI, kanban board, audit trail, collaboration history). Remaining gaps (diagram authoring, video walkthroughs, voice multi-language) are mostly accommodated as new requirements (`WEB-14`, `WEB-15`) or deferred to v2 (voice). PMG team's daily plugin-authoring workload is the ideal Phase 7 validation: real customer requirements → real merged PRs on real motadata-itsm code, dogfood daily.

**Alternatives considered.**
- **Keep Phase 7 abstract** ("validate kernel against motadata-itsm vertical") — vague, no clear acceptance test.
- **Pick a different vertical** (fintech, devops, embedded) — no internal customer; no existing domain expertise; slower feedback loop.
- **Skip vertical work in v1** — kernel ships untested in real org; high risk of architecture misfit.

**Consequences.**
- Phase 7 acceptance criteria become falsifiable: PMG team uses hivecore daily; ≥1 customer requirement → merged PR per week sustained over 4 weeks.
- 2 new v1 requirements added: `WEB-14` (diagram authoring with Mermaid + SVG embed) → Phase 5; `WEB-15` (video walkthrough capture + transcript-to-KG) → Phase 7.
- 1 v2 requirement: `ADAPT-V2-05` (voice support multi-language).
- "Roadshow" requirement interpreted as run-viewer replayable timeline + presentation mode — no new req needed.
- Weekly PMG-head review starting at Phase 4 demo (board + daemon + first Dev persona PR).
- Increases stakeholder investment in motadata; minor risk of vertical-specific drift mitigated by ontology overlay being config (not code).

**Revisit when.** PMG team rejects the workbench shape after Phase 4/5 demos, OR a different first-vertical user emerges with stronger pull.
