# ADR-013 · 2026-04-29 · `shantanugoel/oxydra` as reference implementation (not dependency)

**Decision.** Read `shantanugoel/oxydra` (MIT, Rust, ~55★) source before P4 (`hivecore-persona`) and P9 (config schemas). Adopt patterns: `#[tool]` macro for tool registration with auto schema generation, safety-tier model for tool permissions, multi-user concurrency model, LLM provider abstraction trait. Do NOT depend on the crate.

**Context.** oxydra solves multi-agent orchestration with strong isolation and provider flexibility — overlapping ~40% with hivecore's persona harness scope. Different scope and assumptions overall, so dependency is wrong, but reference patterns are valuable.

**Alternatives considered.** Fork oxydra (over-coupling). Ignore it (lose proven patterns). Vendor specific files (license is MIT — possible but creates ambiguity).

**Consequences.** Faster path to correct patterns. Time investment in reading source before each affected phase.

**Revisit when.** oxydra ships a stable extracted "harness primitives" crate we could depend on cleanly.
