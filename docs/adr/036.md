# ADR-036 · 2026-05-04 · `LifecycleEvent::PreCompact` — observable compaction boundary

**Decision.** Add a new `LifecycleEvent` variant fired before `ContextTransform::maybe_compact` runs:

```rust
// hivecore-runtime-core/src/lifecycle.rs
pub enum LifecycleEvent<'a> {
    // ... existing variants ...
    PreCompact {
        /// Read-only view of the messages that will be folded into the summary.
        to_be_summarized: &'a [AgentMessage],
        /// Read-only view of the messages that will be kept verbatim.
        to_be_kept: &'a [AgentMessage],
        /// Why compaction is firing.
        trigger: CompactionTrigger,
    },
    PostCompact {
        /// The compaction entry that was appended (per ADR-032 schema).
        entry_id: EntryId,
        tokens_before: u32,
        tokens_after: u32,
    },
}
```

`LifecycleHook::on_event` returns the existing `LifecycleOutcome { Pass | FailedContinue | FailedAbort | ManualAttention }`. If any hook returns non-`Pass` on `PreCompact`, the driver skips this round of compaction (treats it as `Ok(None)` from `maybe_compact`) and surfaces the reason to the caller. `PostCompact` is informational — non-`Pass` outcomes are recorded but do not unwind the appended entry (compaction is already on disk per ADR-032).

**Context.** Today compaction fires silently inside `ContextTransform::maybe_compact`. That's load-bearing for the default `SummarizingTransform`, but it leaves no extension point for:

- **Audit.** ADR-019 audit plane wants a discrete event for "compaction window crossed" — currently has to infer from message log diffs.
- **Custom summarisers.** A tenant-specific summariser that wants to inspect `to_be_summarized` before deciding which model to use, or to prepend repo-specific context.
- **KG ingestion.** `Custom { kind: "compaction_marker" }` lands on disk but the *boundary itself* is not an emit-side event the KG pipeline can subscribe to.
- **Operator visibility.** The frontend (P5) wants a "compaction running" indicator; today it would have to diff session state to detect one happened.

The transform-internal compaction continues to work for harnesses that don't wire any `PreCompact` hook — the event is opt-in observation, not a required-handler change.

**Alternatives considered.**

1. **Use an `EventSink` event instead of a lifecycle hook.** Rejected — `EventSink::emit` is fire-and-forget; we need *cancellable* observation (a hook can veto compaction this round). Lifecycle is the right axis.
2. **Make compaction a tool the model calls explicitly.** Rejected — compaction must be deterministic and infrastructure-level; surfacing it as a tool gives the model the option to mis-time it.
3. **One combined `Compaction` event with a `phase: Pre | Post` field.** Rejected — Rust enums distinguishing variants are clearer than enum-with-discriminant for two distinct payload shapes.
4. **Defer until a hook author asks for it.** Rejected — ADR-032 lands tree-shaped sessions, which makes per-branch compaction a real thing; pre-/post-events anchor the audit + KG story before custom transforms proliferate.

**Wiring.** Two new `LifecycleEvent` variants. `crates/hivecore-compaction/src/transform.rs` fires `PreCompact` before computing the summary and `PostCompact` after appending the entry (only on the `Some(marker)` path). ~80 LOC + 6 tests (variants exist, hook can veto via `FailedContinue`, post fires after append, kept-vs-summarised slicing is correct, no-compaction-no-event, abort propagates).

**Consequences.**

*Enables.*
- Custom summariser hooks per ADR-026 §Crate-layout's "replaceable by orgs" goal.
- KG-ingestion subscribes to compaction boundaries cleanly.
- Audit plane gets typed events without parsing JSONL retroactively.
- Frontend gets compaction-progress UI signal.

*Costs.*
- ~80 LOC + tests.
- Two more variants on a non-exhaustive enum; safe.
- Slight risk of hooks abusing `PreCompact` to mutate `to_be_summarized` — addressed by `&[...]` (read-only) signature.

**Revisit when.**
- Custom summarisers want to *replace* the compaction strategy (not just observe). Promote to a real transform hook returning `Option<CompactionPlan>`.
- `PostCompact` consumers need the *content* of the summary inline — currently only id + token counts; resolved by reading the entry from `SessionStore`. If that proves load-bearing, inline `summary: &str` on the variant.
- Branch-summary (ADR-032 `BranchSummary` payload) wants its own `PreBranchSummary` / `PostBranchSummary` lifecycle events — apply the same shape.
