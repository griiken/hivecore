# ADR-014 · 2026-04-29 · UI-first principle + native board+daemon (supersedes earlier "consume multica/paperclip" stance)

**Decision.** Hivecore ships board and daemon natively as part of the kernel. Hivecore is a complete platform, not a substrate-on-top of multica/paperclip. Additionally, every capability is exposed through the Next.js workspace UI as the primary surface; TOML config and CLI are power-user fallbacks. The UI generates the underlying TOML/YAML config so git versioning and AI-agent-readability are preserved.

**Context.** Earlier scope drafts (PROJECT.md initial Out of Scope, .research/00-thesis/non-goals.md) excluded board+daemon as a layer hivecore would consume from external OSS (multica, paperclip, kandev, etc.). Reconsidered for two reasons. (1) **Positioning:** "consumer of multica" is fragile — when multica's project drifts, our pitch drifts. A complete platform pitch is clearer. (2) **Integration cost:** integrating with external board+daemon means perpetual integration tax and weaker KG ↔ daemon coupling than native. (3) **Adoption:** OSS adoption-led wedge needs a polished UI; relying on external UIs splits the user surface and confuses positioning. Building UI-first on a native board+daemon gives one-deploy adoption and no surface fragmentation.

**Alternatives considered.**
- **Consume multica + bring our own UI** — split user surface; weak KG-daemon coupling; multica's roadmap drives ours.
- **Consume paperclip** — paperclip is solo-scale; multi-tenant retrofit is non-trivial.
- **Build board+daemon, no native UI** — TOML/CLI-only adoption is too narrow; competitors (multica, paperclip, AgentsRoom) have polished UIs.
- **Host UI but native daemon** — split deployment story; adoption friction.

**Consequences.**
- Scope grows by ~10 requirements (DAEMON-01..03, WEB-06..13).
- Roadmap grows from 7 to 8 phases; UI work weaves through every phase ≥ P1 instead of being a separate F-track.
- Phase 4 becomes the "first real demo" milestone: native board + daemon + Dev persona + first PR.
- Hivecore now competes head-on with multica/paperclip, not as a layer above them. `docs/comparison.md` updated to reflect this.
- The complete-platform pitch simplifies enterprise sales and OSS positioning.
- More UI investment required up-front; mitigated by Next.js + shadcn/ui shipping fast.

**Revisit when.** UI maintenance cost outpaces value, OR a markedly better OSS UI substrate emerges that we'd want to adopt instead of building, OR multi-tenancy becomes secondary (unlikely).
