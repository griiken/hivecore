# ADR-035 · 2026-05-04 · `PostHookOutcome` early-stop hint

**Decision.** Extend `PostHookOutcome` in `hivecore-runtime-core` with a `terminate` hint:

```rust
// hivecore-runtime-core/src/hook.rs
pub enum PostHookOutcome {
    Pass,
    Replace(ToolOutcome),
    /// Same as Replace, plus a hint that the agent loop should stop after the
    /// current tool batch settles. Early termination only fires if EVERY
    /// finalized tool result in the batch carries `terminate = true`.
    ReplaceAndTerminate(ToolOutcome),
}
```

The driver's `dispatch_tools` collects per-call outcomes; after the batch settles, if all `terminate` flags are true, the inner loop sets `state.stop_reason = StopReason::EndTurn` and breaks before the next `model.complete`. Single dissenter ⇒ loop continues normally — preserves "any tool can keep the conversation alive" semantics.

**Context.** Some tool patterns want to short-circuit the model loop without faking an error: a "submit" tool that ends the agent's task, a "task complete" sentinel from a subagent, a HITL-driven `final_answer` tool. Today the only escape is `HookOutcome::FailedAbort` (pre-hook, error-shaped) or `HookOutcome::ManualAttention` (also error-shaped). Both leak as errors to logs and audit, which they aren't. A clean "we're done; do not call the model again" hint is missing.

**Alternatives considered.**

1. **Use `ManualAttention` for clean termination.** Rejected — semantically wrong, contaminates audit + UI as "needs human."
2. **Add a top-level `LoopOutcome::Stop` from the driver.** Rejected — that's where the existing `StopReason` lives; the hook layer needs to *signal* into it without owning it.
3. **Add a new `Approval` decision variant.** Rejected — termination isn't an approval; conflates two concepts.
4. **AND-across-batch is too strict; OR-across-batch.** Rejected — single tool unilaterally stopping the loop is a footgun (one buggy hook collapses the agent). AND requires consensus, matches "every tool agrees we're done."
5. **Add a `terminate` field on `Replace` instead of a new variant.** Rejected — variants are clearer than struct-with-flag for a binary distinction; hook authors see the choice in autocomplete.

**Wiring.** One enum variant added in `runtime-core`. `dispatch_tools` in `hivecore-agent-loop` collects flags and folds AND. ~30 LOC + 4 tests (single-terminate-no-stop, all-terminate-stops, mixed-pass-and-terminate, replace-vs-replace-and-terminate-equivalence).

**Consequences.**

*Enables.*
- Clean "submit answer" tool pattern.
- Subagents can self-end without faking errors.
- HITL "this is the answer; don't iterate further" flow.

*Costs.*
- ~30 LOC + tests.
- Hook authors (custom tool-policy crates) see a third variant; covered by `match` exhaustiveness, low risk.

**Revisit when.**
- A use case wants OR-semantics (any tool stops the loop) — add `OrTerminate` mode at builder level.
- The hint needs to carry a reason payload for audit — extend variant: `ReplaceAndTerminate { outcome, reason: Option<String> }`.
