# ADR-011 · 2026-04-29 · Postgres 17 + pgvector for KG storage; multi-tenant via Row-Level Security

**Decision.** KG storage backend is PostgreSQL 17 + pgvector extension; multi-tenancy enforced via Row-Level Security with `SET LOCAL app.tenant_id = ...` per request. Upgrade paths to Memgraph/Neo4j (graph perf) or schema-per-tenant/DB-per-tenant (isolation strictness) are documented but not built v1.

**Context.** Hivecore's KG holds nodes/edges/properties + embeddings + audit. Postgres+pgvector serves all four in one system, simplifying ops. RLS is the canonical 2025/2026 pattern for multi-tenant Postgres (DebuggAI playbook). Avoids running two stores (Postgres + Neo4j) at v1; can swap to Memgraph for hot-path graph queries if perf demands.

**Alternatives considered.** Neo4j/Memgraph from day 1 (operational complexity). Schema-per-tenant (heavier migration story). DB-per-tenant (resource overhead). Pure SQLite (no vectors, no scale).

**Consequences.** One store to operate. Recursive CTEs + carefully indexed property-graph schema for graph queries. Upgrade path documented for when perf binds.

**Revisit when.** p99 query latency exceeds 200ms with 100k nodes / 500k edges, OR a tenant needs strict per-DB isolation for compliance.
