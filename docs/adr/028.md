# ADR-028 · 2026-05-01 · Browser harness — hybrid a11y-snapshot + delegated vision (design-only, planning)

**Decision.** A first-party native Rust browser harness lands as **three coordinated Layer-2/Layer-3 crates**: `hivecore-browser-core` (Layer 2, pure `BrowserProvider` trait + capability schema, lifted from jcode's BPP under MIT), `hivecore-browser-runtime` (Layer 3, default `chromiumoxide`-backed daemon with persistent CDP, per-(tenant, session) socket, ref-versioned snapshots, artifact dir, AES-GCM credential vault — patterns vendored from gsd-browser under Apache-2.0 with attribution per ADR-024), and `hivecore-browser-harness` (Layer 3, ~20 typed `Tool` impls). Default observation is the **accessibility tree with opaque versioned refs** (a11y-snapshot first); a **delegated vision fallback** (TesterArmy hybrid pattern) handles canvas controls, payment popups, OAuth flows, custom widgets, and any case where the rendered UI does not match the a11y tree. Coordinates never enter the primary agent's transcript. Multi-tenant isolation enforced at the provider boundary by construction. v0.1 ships with Chromium only via CDP; WebDriver BiDi / Firefox / WebKit / Playwright-MCP-as-provider deferred to v0.2. **Implementation defers to v0.2; the contract is locked here so build is a single pass.**

**Context.** Surveyed eight browser-harness reference points at HEAD on 2026-05-01: gsd-build/gsd-browser (Rust + chromiumoxide daemon, 63 commands, versioned refs, Claude-Code-style skill), 1jehuang/jcode (formal Browser Provider Protocol with capability tiers, per-session bridge, Firefox extension), microsoft/playwright-mcp (TS MCP server, ~35 typed `browser_*` tools, snapshot-first stance), browser-use (whole agent, wrong layer), browser-use/browser-harness (thin CDP shim, agent-edits-harness model — too loose for substrate), Browserbase Stagehand (hosted SDK), ServiceNow BrowserGym (research benchmark runner), and TesterArmy's published (2026-04-30) hybrid-vision argument. Findings in `.research/browser-tools.md` (~190 lines) and `.planning/intel/browser-harness.md` (decision-ready distillation).

The dominant 2026 pattern is unambiguous: **a11y-tree-first + opaque versioned refs + persistent daemon + provider abstraction**. TesterArmy's correction is real and load-bearing for an SDLC harness: agents will test apps we do not control, and many real customer apps have inaccessible widgets, popups, and visual-only states. Pure-DOM purity loses; pure-pixel computer-use loses on speed and stability. Hybrid (snapshot default, vision delegated fallback) wins.

**Decisions.**

1. **Three-crate split.**
   - `hivecore-browser-core` — Layer 2, no I/O. `BrowserProvider` trait, `Capability` schema with stability tiers (`stable | experimental | not_implemented`), snapshot/ref/action types, multi-tenant `session_id` carrying `tenant_id`. Lifted from jcode BPP (MIT).
   - `hivecore-browser-runtime` — Layer 3, owns the daemon. `chromiumoxide` for CDP. Per-(tenant, session) UNIX socket under `<sessions_dir>/<tenant_id>/<session_id>/browser/`. Patterns vendored from gsd-browser (Apache-2.0, ADR-024 precedent).
   - `hivecore-browser-harness` — Layer 3, the Tool adapter. Consumes `Arc<dyn BrowserProvider>`. Default-wired in `hivecore-coder` and `hivecore-acp-server` with `--no-browser` opt-out.

2. **Tool surface ~20 typed tools.** Names align with Playwright MCP convention. `browser_act` is one tool with a typed `kind` enum, not a separate tool per click/type/hover — keeps the model's tool-list compact:
   ```
   browser_session, browser_navigate, browser_back, browser_forward, browser_reload,
   browser_snapshot, browser_act, browser_wait, browser_assert,
   browser_screenshot, browser_extract, browser_network, browser_console,
   browser_eval, browser_trace,
   browser_scene_understand, browser_vision_click
   ```

3. **A11y-snapshot first, vision-delegated fallback (TesterArmy hybrid).** `browser_snapshot` is the default observation channel. `browser_scene_understand` (capture screenshot, return compact scene summary, flag a11y/visual mismatches) and `browser_vision_click` (`{ element: <intent text> }` → vision model resolves coordinates → click → fresh snapshot) fire only when snapshot lacks a match, a ref went stale post-resnapshot, or the user explicitly requests visual targeting. **Coordinates never enter the primary agent's transcript** — they live in `ToolOutcome.details` for audit only.

4. **Versioned refs, stale-on-navigation invariant.** All actions reference opaque versioned refs returned from the latest `browser_snapshot`. Stale refs return a typed `StaleRef` error — never silently resolve. Re-snapshot is the agent's responsibility; convenience methods return a fresh snapshot inline so the next turn doesn't have to ask.

5. **Multi-tenant by construction.** `tenant_id` flows through every BPP call. Provider refuses cross-tenant page handles. Per-tenant credential vault (AES-GCM + Argon2 keyed by `tenant_id`) — vault key derived from passphrase plus tenant id; cross-tenant decrypt impossible. Per-(tenant, session) daemon for isolation (pool optimisation v0.2).

6. **Safety model.**
   - **Loopback-only daemon socket** — UNIX socket under per-tenant runtime dir; no remote control.
   - **Artifact root confinement** — screenshots, traces, HARs, downloads bounded to `<sessions_dir>/<tenant_id>/<session_id>/browser/`.
   - **URL allow/deny config** — per-agent TOML.
   - **Sensitive-action hooks** — `BrowserHook` trait (analog of `ToolHook`) fires before credential entry, payment forms, CAPTCHA, file upload/download. Audit-logged; harness can require Gate-plane approval.
   - **Always-on prompt-injection scan** — `check-injection` (gsd-browser pattern) on every page text returned to the model; matches tag the snapshot.
   - **`browser_eval` capability-gated** — off by default. Per-agent `[agent.browser] allow_eval = true` to enable. RCE-equivalent — always audit-logged.

7. **Performance budgets** (gates, not asserts; measured by test plan):
   - Warm `browser_snapshot` (medium page) < 150 ms
   - Warm `browser_act` < 100 ms
   - `browser_screenshot` < 500 ms
   - Cold daemon start (Chrome installed) < 2 s
   - `browser_vision_click` full round trip < 5 s
   Regressions on warm-path budgets block merge.

8. **Vision model wiring.** Default to the agent's configured chat model if vision-capable; per-agent override `[agent.browser] vision_model = "..."`. Vision delegation runs in its own model call so the primary agent's loop stays coordinate-free.

9. **License vendoring.** Apache-2.0 (gsd-browser) and MIT (jcode BPP) both compatible with hivecore's MIT-OR-Apache-2.0. Vendored files carry header pointing back to source URL + license + sync date (ADR-024 precedent). Playwright MCP patterns adopted (naming convention, snapshot stance) but TS code not directly vendorable — re-implemented in Rust. Browser Use AGPL is not relevant; their MIT-licensed `browser-harness` repo is too thin to vendor and the agent-edits-harness pattern is rejected.

**Alternatives considered.**

- **Wrap gsd-browser CLI directly.** Couples our public Tool API to another tool's CLI semantics. Loses typed `Tool` schemas. Rejected — vendor patterns instead.
- **Playwright MCP as default provider.** Strong Firefox/WebKit coverage but TS/Node runtime, requires our v0.2 MCP layer to ship first, and skipping a native impl loses our ability to enforce multi-tenant isolation by construction. Rejected for v0.1; revisit as v0.2 alt provider.
- **Pure DOM-based addressing (browser-use index pattern).** Drift-prone; fails on hidden a11y nodes and inaccessible widgets. Rejected.
- **Pure pixel / computer-use.** Loses speed, token cost, scene awareness, stable form semantics. Rejected as default.
- **Vision as parallel default (not fallback).** Token cost explodes; primary agent ends up reasoning about coordinates; auditability degrades. Rejected — TesterArmy's argument is for vision as fallback, not as co-default.
- **Single stringly-typed `browser` tool with `action` enum (jcode shape).** Operationally fine but harder for models to use; the typed-tool-per-action style (with `browser_act` as one `kind`-enum tool to avoid explosion) is the broader convention. Rejected.
- **Browser Use `browser-harness` self-editing pattern.** Agent edits the harness mid-task to add primitives. Too loose for a multi-tenant substrate; mid-flight harness mutation breaks reproducibility and audit. Rejected.
- **`browser_run_code_unsafe` exposed by default (Playwright MCP).** RCE-equivalent. Capability-gated behind `allow_eval` instead.
- **Single-daemon-per-tenant pool.** Faster but couples session lifetimes. Rejected for v0.1; revisit as v0.2 optimisation if cold-start budgets bind.

**Consequences.**

- v0.1 ships without browser tooling. v0.2 adds three crates, ~1500 LOC across them.
- Hybrid pattern: agents on simple semantic UIs use only `browser_snapshot` + `browser_act`; messy real-world apps fall back to delegated vision.
- Coordinate-reasoning, raw screenshots, and vision model calls stay out of the primary agent's transcript by default. Reduces token bill and prompt-injection surface.
- Multi-tenant browser sessions actually work (no other surveyed tool supports this).
- Per-tenant credential vault makes credential reuse safe across runs without leaking cross-tenant.
- WebDriver BiDi / Firefox / WebKit support deferred — accept as a real coverage gap until v0.2 alt provider lands.
- Cost: three crates, one default Cargo dep on default harnesses, one config file path for browser settings, daemon process lifecycle to manage, vision-model dependency for fallback path. Performance budgets enforced.

**Revisit when.** (a) Cold-start budget binds in CI or production — pool daemons per-tenant. (b) Token cost from vision delegation grows large — investigate scene-summary caching by URL+DOM-hash. (c) Tenant-supplied browser drivers needed — standardise WebDriver BiDi adapter. (d) Browser Use BiDi or a future open standard for agent browser control matures — adopt as alt provider. (e) `chromiumoxide` upstream stalls or breaks compatibility — pin and vendor the snapshot we depend on. (f) An MCP-shaped browser provider (`hivecore-browser-playwright-mcp`) becomes a distribution priority — separate ADR.
