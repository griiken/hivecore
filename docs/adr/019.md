# ADR-019 · 2026-04-30 · Seven-plane orchestration kernel (UOK + Tenancy plane)

**Decision.** Hivecore Layer 3 ("hivecore-classic") implements a seven-plane orchestration kernel. Each plane is a separate `*-core` crate (I/O-free traits + types) plus optional `*-runtime` crate (I/O impls). Planes:

1. **Plan plane** — produces unit specs with acceptance criteria, verification strategy, ownership, rollback semantics. Plan-gate fail-closed if any field missing.
2. **Execution plane** — runs units in fresh agent sessions per unit; pre-inlines slice plan + summaries + decisions into dispatch prompt.
3. **Routing plane** — model + persona selection per unit (renamed from GSD's "Model plane" — must consider persona + tenant + cost).
4. **Gate plane** — typed validators at six points (`policy`, `input`, `execution`, `artifact`, `verification`, `closeout`). Outcomes: `pass | retryable-fail | hard-fail | manual-attention`. Bounded retries, escalating strategy, sliding-window stuck detection.
5. **GitOps plane** — per-turn git transaction (`turn-start → exec → stage → checkpoint → publish → record`); configurable `commit | snapshot | status-only` per phase.
6. **Audit plane** — append-only JSONL events + SQLite/Postgres projection. Every event carries `event_id`, `trace_id` (session), `turn_id` (unit), `caused_by`, `tenant_id`, `timestamp`, typed payload. Event classes: orchestrator, model, tool, git, test, policy, cost, **kg**.
7. **Tenancy plane (hivecore-unique).** Multi-tenant retrieval-time isolation. KG queries flow through tenant-scoped views; provider-side prompt isolation is rejected as insufficient. Every event payload, every tool call context, every KG handle carries `tenant_id`. The tenancy plane owns the security boundary.

Per-turn pipeline: `Discover → Plan-compile → Route → Execute → Gate → Git → Audit → Next`. Three-tier timeouts (soft 20m / idle 10m / hard 30m). Context-pressure monitor at 70% triggers wrap-up.

**Context.** GSD-2 ADR-009 introduced UOK with six planes. Studying its design + ADR-013 (memory-surface consolidation pain) + ADR-011 (progressive planning) shows this is the most coherent OSS orchestration architecture seen so far. Hivecore inherits the structure, renames Model→Routing for clarity, and adds the Tenancy plane because hivecore's multi-tenant + retrieval-isolation thesis is not addressable as a feature within an existing plane — it cuts across all of them and must be its own enforcement layer.

**Alternatives considered.**
- **Skip plane decomposition; one orchestrator crate.** Easier to start, harder to evolve. Rejected — GSD's pain shows the planes need explicit boundaries.
- **Six planes (no Tenancy).** Push tenancy into Audit + Gate. Rejected — security boundary deserves its own crate; auditability of tenancy enforcement requires separation.
- **Eight+ planes.** Considered: Cost plane (separate from Audit), Cache plane. Rolled into Routing + Audit for v0.1. Revisit if they grow heavy.

**Consequences.**
- Crate count: ~14 Layer 3 crates (`hivecore-{plan,execution,routing,gate,gitops,audit,tenancy}-{core,io}`). Big but enforced via I/O-free rule.
- Audit event schema is the durable contract — adopt `event_id/trace_id/turn_id/caused_by/tenant_id/payload` shape from day one.
- v0.1 MVP includes minimal Plan, Execution, Gate (just the 4 outcomes), Audit, and Tenancy (in-memory tenant context). GitOps + Routing get stubs; full impls v0.2+.
- Layer 3 is replaceable: an org could ship `hivecore-uok-strict` or `hivecore-uok-lite` as alternative defaults.

**Revisit when.** A plane consistently has trivial impl (merge with neighbor); or a new concern emerges that doesn't fit any plane (split out).
