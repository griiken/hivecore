# ADR-033 · 2026-05-04 · `Role` overlay above `Agent` (call/session/agent precedence)

**Decision.** Add `Role` as a first-class CONFIG type in `hivecore-config`, lighter than `Agent`. A `Role` is a system-prompt fragment plus an optional tool allowlist; it overlays an `Agent` at three scopes — **call**, **session**, or **agent default** — with precedence `call > session > agent`. Roles are TOML-declared (one file per role under `.hivecore/roles/<name>.toml`), discovered by the same loader that handles agents, and applied as a *system-prompt-overlay* in `hivecore-system-prompt` — never injected into persisted user message history.

**Schema:**

```toml
# .hivecore/roles/researcher.toml
name = "researcher"
description = "Read-only investigation; no file edits, no shell."

# Appended to the agent's base system prompt at the role's scope.
prompt = """
You are operating in researcher mode. Your job is to read, search, and
summarise. Do not edit files. Do not run shell commands that mutate state.
Use read_file, grep, and structured search tools only.
"""

# Optional. If present, replaces the agent's tool list at this role's scope.
# If absent, role inherits the agent's tools.
tools = ["read_file", "grep", "list_dir"]

# Optional. If present, takes precedence over agent's model preference at this scope.
# model = "anthropic/claude-haiku-4-5"
```

**Trait + plumbing:**

```rust
// hivecore-config/src/role.rs
#[derive(Debug, Clone, Deserialize)]
pub struct Role {
    pub name: String,
    pub description: String,
    pub prompt: String,
    pub tools: Option<Vec<String>>,
    pub model: Option<String>,
}

// hivecore-system-prompt
pub struct SystemPromptInputs {
    pub agent_base: String,
    pub agents_md: Option<String>,
    pub skills_index: Option<String>,
    pub role: Option<Role>,    // NEW — applied last, after agents_md
    pub appended: Option<String>,
}
```

Precedence resolution at turn boundary (in the harness, not the driver):

```rust
let role = call_role
    .or(session_role.clone())
    .or(agent_role.clone());        // agent default

let tools = role.as_ref()
    .and_then(|r| r.tools.clone())
    .unwrap_or_else(|| agent.tools.clone());

let model = role.as_ref()
    .and_then(|r| r.model.clone())
    .unwrap_or_else(|| agent.model.clone());

let system_prompt = build_system_prompt(SystemPromptInputs {
    agent_base: agent.system_prompt.clone(),
    role,
    /* ... */
});
```

**Context.** `hivecore-config` ships `Agent` (renamed from Persona per ADR-021). An agent is a heavyweight construct: full system prompt, tool list, model preference, lifecycle config, compaction settings. Two friction points have surfaced:

1. **Sub-agent specialisation.** `SpawnAgentTool` (in `hivecore-agent-loop`) lets a parent delegate; today the only knob is which `Agent` to spawn. For a coder spawning a "researcher" subagent, declaring a full secondary `Agent` is over-modelling — the researcher shares the model, compaction, and most of the prompt with its parent; only the *role guidance* and tool subset differ.
2. **Per-call mode switching.** `/plan` mode, `/research` mode, `/edit` mode are common UI affordances. Today these would either be (a) full agent switches (heavy, breaks session continuity) or (b) raw system-prompt-injection at the harness layer (untyped, untracked, untestable). A first-class overlay type makes the affordance cheap and auditable.

`Role` is the lightweight overlay. It does *not* replace `Agent`; it composes onto an active agent. An agent is a what-you-are; a role is a how-you're-acting-right-now.

**Alternatives considered.**

1. **Ship `Role` as just another `Agent`, suspend/resume between them.** Rejected. Loses session continuity (each switch is a session boundary), loses cumulative context (agent A's discoveries don't carry into agent B), inflates the audit trail. Roles compose; agents don't.
2. **Inline `prompt` strings into `SpawnAgentTool` arguments.** Rejected. Untyped, no discovery, no reuse across calls, can't be authored in markdown by repo maintainers. Violates ADR-007 (config not code).
3. **Single global `[agent.modes]` table inside `Agent` TOML.** Rejected. Modes ↔ roles is N:M (a researcher role may apply to coder *and* reviewer agents). Separating Role out preserves that.
4. **Make `Role` carry full lifecycle config like `Agent`.** Rejected. Heavy. The point of the overlay is that 90% of behavior comes from the agent; the role only flips the dimensions where roles meaningfully differ (prompt, tool subset, optional model override).
5. **Precedence agent > session > call (call yields to session).** Rejected. Industry default and user expectation: explicit-now beats sticky-session beats config-default. Hivecore matches.

**Wiring plan.**

| Crate | Change |
|---|---|
| `hivecore-config` | New `role.rs`: `Role` type + TOML parser. Loader gains `RoleRegistry` alongside the existing agent registry; same `.hivecore/<scope>/<file>.toml` waterfall (user / project / temporary, per existing config layering). |
| `hivecore-system-prompt` | `SystemPromptInputs` gains `role: Option<Role>`. Builder appends `role.prompt` after `agents_md`, before `appended`. No template change in vendored Codex/Zed prompts; role guidance lives at the harness layer above them. |
| `hivecore-agent-loop` | `AgentState` (or a new `TurnContext`) carries the resolved `Option<Role>` for the current turn. Driver passes it into `transform_outgoing` so the system prompt is rebuilt on role switches. `SpawnAgentTool` arguments gain optional `role: Option<String>`. |
| `hivecore-coder` | CLI flag `--role <name>` (session-scoped). Slash command `/role <name>` (session-scoped). `/role <name> --once` (call-scoped). |
| `hivecore-acp-server` | ACP `session/load` accepts a `role` field; per-prompt requests accept a `role` override. Wired through ACP custom-extension space until upstream protocol acquires the concept. |

**Consequences.**

*Enables.*
- Cheap mode switching (`/research`, `/plan`, `/edit`) without re-spinning agents.
- Sub-agent specialisation by role rather than by separate agent declarations.
- Composable roles across multiple agents (one researcher role applies to coder, reviewer, designer — author the prompt once, reuse).
- Auditable role transitions in the session log (a `LeafChange` plus role state in the `Custom` payload — orthogonal to ADR-032).

*Costs.*
- ~250 LOC for the type + loader + builder integration.
- One new schema in `.hivecore/roles/`; documented in CONTRIBUTING + AGENTS.md.
- Test surface: ~10 new tests covering precedence, tool override, model override, missing-role error path.
- Frontend (apps/web, future) needs a UI for role picking — tracked under P5 visual editor.

**Revisit when.**
- Roles need lifecycle hooks (e.g., a `researcher` role auto-mounts a different `RiskAugmenter`). Add `Role.lifecycle = ...`.
- Roles need per-tool argument shaping (e.g., a `safe-edit` role forces `dry_run = true` on `edit_file`). Add `Role.tool_args_overlay`.
- Cross-tenant role sharing becomes a feature — tenant-scope vs global-scope roles, akin to ADR-027 MCP server scoping.
- A research finding shows a richer overlay axis (prompt + tools + model + memory_filter) — extend the Role schema.
